## 3. ⭐ 라우팅 — 계층 구조 vs 평면 구조

### 🔥 "졸업할 때까지 5번은 반복합니다"
제가 수업시간에 항상 (하는) 중요한 이야기는, 여러분들이 **졸업할 때까지 대략 한 5번 정도 반복**을 시작합니다. (그래도) 계속 못 듣는 학생들이 생기고 그래서 다 안 (되는) 경우가 (있어요).

항상 제가 이야기하지만, 이렇게 이야기를 하면 🔥 **"저게 무슨 의미인가"를 꼭 짚으시길 바라고, 의미가 (잘 안 잡히면) 개인적으로 꼭 자료를 찾아서 읽고 이해하고** (정리하세요).

### ⭐ 라우팅 = 길 찾기 — 두 가지 구조
**라우팅**이라고 이야기하는 것은 결국 L3에서의 (이야기고), 이번 학기 여러분들하고 (계속) 하고 있어요.

라우팅이라고 이야기하는 게 레이어 3에서는 기본적으로 (핵심이) 됩니다. 이 라우팅은 — **데이터 전달을 전제**로 하는데, 이게 **end-to-end** (전달)을 하는 방식을 (말하)겠죠.

(방식이 두 가지 있습니다)
- ⭐ **계층 구조** — 다른 말로 하면 **위계 구조** 이렇게 표현할 수 있습니다. 영어로 **Hierarchical Architecture**.
- ⭐ 또 다른 하나의 방식이 **평면 구조** — 영어로 **Flat Architecture**. "플랫한 구조를 가진다" 이런 용어도 있어요.

### 🔥 "전화번호, IP address"는 대표성일 뿐
자, 이후의 의미가 뭐냐 하면 — (슬라이드에) 이거의 쓰임새가 "**전화번호**" (이렇게 적혀 있지만) 꼭 그렇지는 않습니다. **이게 대표성을 가진 겁니다.**

(학생에게) 세로로 와 보세요. (잘 안 들림)

자, 이렇게 적으면 이 말이 어떤 의미를 가지게 되냐면 — 전화번호가 당연히 전화(망)에서 쓰이는 건데, **계층 구조적인 데이터 전달이 (가능하도록) 쓰여지는 겁니다.** 그렇죠?

(평면 구조는) 어떤 (예)가 되었어요? **IP address** 이렇게 이야기했어요. 흔히 우리가 저기에서 **IP address**라고 적었고요, **인터넷**이라고 적었지만, 🔥 **저게 대표성을 띠는 거지 꼭 이것만 평면 구조인 건 아니에요.**

🔥 **라우팅이라고 하는 것은 하나의 구조적인 동작에 해당하는 용어다.** 라우팅 = **길 찾기**라고 그랬죠. 길 찾기인데, **데이터 전달을 (출발지)에서 (목적지)까지 갈 때 어떤 길로 갈 것인가.**
- 그 길이라고 이야기하는 게 **위계 구조(Hierarchical)** 를 가질 수도 있고, **플랫 구조(평면 구조)** 를 가질 수도 있는데,
- 그때 사용되는 (주소)는 **전화번호, IP address** 이런 형태로 주어질 수 있다.

라우팅에 대해서는 지속적으로 (나올 거고), 이후에 (잘 안 들림) … 아마 **4학년 때 집중적으로 저 계층 구조**가 또 이야기가 (나옵니다). 이 정도 개요를 이야기합니다.

## 4. 💬 스위치 네트워크 그림 — "대학에서 이 그림으로 강의하는 사람은 없을 것"

이런 그림은 — 이런 그림을 제가 작년에도 이야기했고 올해 또 이야기를 하는데 — (잘 안 들림) … **대학교에서 이런 그림 갖다 놓고 강의를 하는 사람은 없을 것 같아요.** (하자니 다 해 본 거고, 안 하자니…)

그럼에도 하는 이유가 있습니다. 여러분들이 **KT** 가고 싶어 하는 사람 있다고 하죠. KT에 (기술)직으로 발령받아서 가는 친구들 대다수가 — 행정직이 아니면 **장비를 관리**하는 (일을 해요). 장비 관리하러 다니면 **저 장비들 보게 됩니다.** "저 장비가 뭐냐"고 물으면 —
- 하나도 모르고 장비를 만지는 사람과,
- 🔥 **어떤 내용을 알고 "이 장비가 무엇이다"라는 것을 알고 만지는 사람**은 (다릅니다). 본인 스스로의 (자존감)뿐만 아니라 (잘 안 들림) … 가지는 것도 다르다.

### ⭐ 스위치 네트워크 = 평면 구조
이게 무엇을 나타내냐 하면 — **스위치가 이런 식으로 (연결되어) 있다** 합니다.

**스위치 네트워크**라고 이야기하는 것은 (데이터를) 보낼 때 스위칭을 하겠죠. 그래서 스위칭을 하는 그 **연결 구성도가 이런 식으로 그려진다.** "이건 뭐 당연한 이야기겠지" 라는 생각이 들죠.

근데 저 구조는 우리가 지금까지 배운 — **토폴로지**라고 이야기하는 관점으로 보면 — **어디에 가까울까요?** 라고 보면 **해당 사항이 없을 수 있습니다.**

그렇기 때문에 이런 것들을 우리가 어떤 거라고 하냐면 — 🔥 **실제로 이 구조가 조금 전에 이야기를 했던 플랫한 구조(평면 구조)로 보인다.** 바꿔서 이야기하면 **계층 구조(위계 구조)가 안 나오는 거예요.** 그러면 이런 것을 **평면적이다** 라고 이야기합니다.

### ⭐ 경로가 몇 개?
그래서 이제 무엇을 하느냐 하면 — 데이터가 (그림의) SW라고 적은 저 스위치에서 어느 end로 간다고 해요. end-to-end라고 봤을 때 이것이 end다. **A에서부터 F로 보낸다** 라고 이야기를 하는데, **보낼 수 있는 경로가 몇 개가 나올까요?** — 여러 개죠.

- 🔥 **계층 구조(위계 구조)는 보낼 수 있는 경로가 기본적으로 한 개밖에 안 나오는 경우**가 됩니다. 왜 그러냐면 위계 구조 한번 생각을 해 보세요. 여기 있는 기기에서 여기 있는 기기로 보낸다고 하면 **라우팅 경로가 하나밖에 안 나와요. 다른 경로는 없어요.**
- 근데 이거(평면 구조)는요 — **몇 개가 나오는지 모르겠어요.** 어느 쪽으로 가도 **데스티네이션(목적지)** 으로 도착했습니다.

이 경우는 (경로가) 어디로도 갈 수 있다. **일의적이지 않다.** 이런 경우는 어떻게 돼요? 이런 경우는 🔥 **스위치가 (경로를) 결정하는 것**입니다.

### ⭐ 계층 구조는 어디에? → 이동통신망
계층 구조적인 것의 특징은 뭐냐 하면 — **얘는 얘한테 매달려 있고, 얘는 얘한테 매달려 있어.** 이게 지금 어디에 쓰이고 있다? 🔥 **이동통신망에 쓰이고 있다.** 그래서 **4학년 때 무선통신망공학** 시간에 나오죠. 이동통신망 **2G, 3G, 4G, 5G, 6G** 계속 가요. **계층 구조가 계속 이어집니다.**

### 💬 그런데 왜 학교에서 장비(구조)를 잘 안 가르치나?
1. 저 구조를 공부하신 분들이 **이제는 별로 없어요.** (교수님들이 별로 없음)
2. 두 번째 이유는 — 이미 예전에 이런 장비들은 **1990년대 ~ 2000년대 초**까지, 짧게 잡으면 **2010년**, 조금 더 보면 **2015년** 정도까지 **저 장비들의 개발이 거의 완료**가 되어서, 이제는 **속도나 기능 개선** 같은 것들이 이슈가 되어 있는 상황 같아요.
   - 그러니까 그냥 별다른 (연구) 없어도 그냥 만들고, 그런 원리를 그대로 만들면 이런 네트워크 적용을 할 수 있는 상황이 되어 있기 때문에 **특별한 R&D 연구가 없습니다.**

🔥 **그럼에도 불구하고 공부해야 되는 이유는 뭐라고 했어요? 나중에 엔지니어로 취업해서 들어가면 이 장비를 만져야 될 수 있다.**

그래서 저 구조를 **평면 구조**라고 이야기를 합니다.

## 5. ⭐ Switched Network의 분류 — Circuit / Message / Packet

이제 서서히 인터넷 쪽으로 조금 갔다가, **서킷 베이스 네트워크** 갔다가 왔다 갔다 할 텐데요. 앞으로 여러분들은 시간이 지나면 지날수록 **인터넷 관련 — 패킷 스위치 네트워크** 이야기들이 점점 더 강화가 되고, **3학년 때는 주로 저 내용으로** 많이 가요.

**스위치드 네트워크**라고 이야기를 하면 —
- ⭐ **서킷 스위치 네트워크** — 제가 이거는 **서킷 베이스 네트워크(CBN)** 라고 이야기하는 거죠.
- ⭐ **패킷 스위치 네트워크** — 제가 여러분들한테 이야기할 때는 **패킷 베이스 네트워크(PBN)** 입니다.
- ⭐ **메시지 스위치 네트워크** — 🔥 **거의 사라져 가고 있습니다.**

왜? (기술이) 이렇게 진화가 되어서 거의 **패킷으로 통일**된 겁니다. 메시지 스위치 네트워크라고 하는데 **메시지 단위**로 하는데 — 메시지라고 이야기를 하는 것이 **사이즈가 얼마예요?** (정해져 있지 않죠.) 그래서 **패킷으로 통일**이 되어 가는 (거예요).

### ⭐ Packet Switched Network = Datagram Network (+ Virtual Circuit)
여기에 보면 "패킷 스위치 네트워크다" 라고 이야기하고, 다시 **데이터그램 네트워크**입니다. (괄호)로 묶었기 때문에 두 번째.

🔥 **우리가 흔히 이야기하는 패킷 베이스 네트워크 그러면 대부분 이걸(데이터그램) 생각합니다.** 그러면 데이터그램 네트워크라고 이야기를 하는 겁니다.

## 6. ⭐ 데이터그램 — L4 세그먼트 → L3 패킷 → L2 프레임

**데이터그램** — 파일이 하나가 있어요. 이 파일 전체를 주욱 보내는 것을 데이터그램 방식으로 데이터 보낸다고 생각하면 돼요. 그런데 이 파일을 **그대로 통째로 보내는 게 아니라 패킷 단위로 잘라요.**

🔥 **이걸 어디에서 자르냐 하면 — 실제로 처음 자르는 곳은 레이어 4에서 자릅니다.** (잘 안 들림)

(비교하면) **서킷 베이스는 심플해요.** 자원 점유 방식. (잘 안 들림) … **커넥션 오리엔티드** 이런 거 저한테서 여러 번 들었습니다. 그 기술이 적용이 되기 때문에 (경로가) 하나밖에 없어요.

**패킷 스위치 네트워크는 데이터그램 방식과 버추얼 서킷**이라고 되죠. 우선 데이터그램부터 —

아까 이야기했던 것처럼 파일이 있을 때 레이어 4가 (파일을 쪼개는 게) 첫 번째 단계 —
- ⭐ **레이어 4**가 쪼갠 것을 → **세그먼트(Segment)** 라고 (합니다).
- ⭐ 레이어 4의 이 세그먼트가 내려와서 **레이어 3**에 오면 이걸 **패킷화**시킵니다.
  - 🔥 여기에서 **쪼개진 사이즈가 그대로 패킷이 되는 게 아니고, 여기에서 다시 쪼개질 수 있습니다.**
- ⭐ 그 다음에 **레이어 2**로 내려와서 이 패킷 한 개가 **다시 쪼개질 수 있어요.** 다시 쪼개지면 재조립이 될 수 있는데, 그거를 **프레임(Frame)** 이라고 합니다.

그래서 🔥 **이 데이터 사이즈가 — 헤더를 포함한 패킷이나 프레임이나 세그먼트의 크기를 이야기하는 게 아니라 — 페이로드(Payload)에 들어가는 데이터의 사이즈와, 레이어 2·3·4가 다 다를 수 있습니다.**

어쨌든 이런 것들로, 이런 식으로 보내는 네트워크 방식을 **데이터그램 네트워크**라고 이야기합니다. 이런 것들을 통해서 — 그냥 **패킷 베이스 네트워크, 패킷 스위치 네트워크**라고 이야기하는 분야(입니다).

## 7. 🔥 서킷 스위칭 vs 패킷 스위칭 — 경로가 언제 정해지나

그러면 이제 다시 — **서킷 스위칭 방식과 패킷 스위칭 방식**은, 데이터 전달하는 측면에서 보면 —
- ⭐ **서킷 스위치**: 데이터 보낼 때 **정해진 데이터 패스(데이터가 지나가는 경로)가 지정되는 방식**.
- ⭐ **패킷 스위치 네트워크**: **패킷 한 개 한 개가 임의의 경로**를 통해서 데이터가 (전달)된다.

이렇게 강의를 합니다.

### 예: 패킷 1, 2, 3, 4가 서로 다른 길로
(그림) … 이 (파일)이 이렇게 쪼개지게 되면 — 레이어 (4)가 (자른) 이것을 **세그먼트**, 이것 한 개를 세그먼트 … (잘 안 들림) … 그럼 이 **패킷이 여기서 보내지기 시작**합니다. 보낸 이거를 **1번 패킷, 2번, 3번, 4번**이라고 한다면 —
- 1번은 이렇게 통과해서 가요.
- 2번은 이렇게 가다가 이렇게 바꿔서 (가요).
- 3번은 이렇게 가다가 여기 2(번 스위치)로 와요.
- 4번은 이렇게 가다가 이렇게 꺾고 이렇게 가는 거예요.

제가 조금 단적으로 표현을 하게 됐는데, 🔥 **1번·2번·3번·4번이 전부 다 데이터 패스가 다 달라요. 이게 가능한 게 패킷 스위치(패킷 베이스) 네트워크입니다.**

### ⭐ 왜 이렇게 하나 — 라우터가 그 시점에 최적 경로 선택
왜 이렇게 하냐 하면 — 1번 패킷이 도착했을 때 **네트워크 장비(라우터)** 가 판단했을 때, **현재 시점에서 이 경로가 제일 좋다**고 하는 것을 선택을 합니다.
- 그러니 1번 패킷이 갈 때의 경로는 그 당시에는 저게 제일 좋았고, 2번·3번·4번도 마찬가지.
- 패킷이 보내질 때마다 **라우팅 경로의 상황이 제일 좋은 쪽**을 선택을 하거나, 또는 **라우팅 알고리즘**에 의해서 정의된 형태의 경로상에서 그중에 **가장 좋은 퍼포먼스(성능)** 를 나타낼 수 있는 경로를 선택한다.
- 그렇기 때문에 **패킷마다 지나가는 경로가 다르지.**

자 그러면 이제 다시 이야기를 한다고 하면 —
🔥 **데이터그램 방식 = 패킷 베이스 네트워크 방식은 패킷 단위로 라우팅을 시킨다. 이게 핵심 포인트예요.**

## 10. ⭐ 오버레이(Overlay) 다시 설명 — Physical Bus 위의 Logical Ring

오버레이 있는 쪽을 다시 설명해 줄게요. **네트워크 토폴로지가 뭐예요?** (잘 안 들림)

우리가 이 **버스 타입**을 — **physical, real device가 버스 타입 topology를 가지고** 있다. (잘 안 들림)
- 모두가 **1, 2, 3, 4** 이렇게 (버스에 매달려) 있는 것을, 어떻게 바꾸냐 하면 —
- "**1 → 2 → 3 → 4 → (다시 1)**" 이렇게 하자 라고 합니다.

뭐라고 하냐 하면 — **피지컬 토폴로지는 버스 타입인데, (링을) 오버레이시키는 거**다. 그래서 프로토콜의 방식을 어떻게 하면 되냐 하면 —
- "야, 너 (1번) 데이터 있으면 **2번으로 전달**해."
- "2번은 **3번으로** 줘."
- "3번은 **4번으로** 줘."
- "4번은 (다시 **1번으로**) 줘."

이런 식으로 돌면 뭘 어떻게 하는 겁니까? 🔥 **마치 링처럼 보이잖아. 마치 링(Ring) 토폴로지처럼.**

그래서 —
- **하드웨어 구성**(을 이야기할 때) → **피지컬 네트워크 토폴로지** (물리적인 현상)
- 우리가 "프로토콜이 뭐 이렇습니다"라고 이야기하면 머리 아프니까 → **"오버레이 네트워크다", "로지컬 네트워크 토폴로지다"** 라고 이야기하면 —
  (하드웨어는) 어떤지 모르겠는데, **소프트웨어 쪽으로 로지컬하게 (링으로) 동작**하게 (한 거죠).

그러면 **(링) 타입으로 데이터 주고받는 것도 가능**하고, 그래서 "**(링)이 오버레이 되어 쳐져 있다**" 이렇게 이야기합니다. 알 수 있습니까? 이해 갔죠? 그죠?

### 🔥 Virtual / Logical / Conceptual vs Overlay — 뉘앙스 차이
그래서 **버추얼**이라고 이야기를 할 때는 (잘 안 들림) … 약간 (의미)는 비슷하게 느껴지는데, 뉘앙스가 (다릅니다).
- ⭐ **오버레이 됐다**고 이야기하는 것은 — **원래 토폴로지가 있는데, 그 위에 토폴로지가 더 걸쳐서**. 그럼 실체 토폴로지는요? 실체 토폴로지는 원래 **피지컬 토폴로지**예요. 오버레이 됐다는 이야기는 🔥 **뭔가 다른 거 하나 더 쳐 놓은 것처럼 보이게 만드는 것.**

(잘 안 들림) … 그래서 **버추얼, 로지컬, 컨셉추얼** 이런 다른 어휘 — 개념이 아주 심플한데 **핵심이 있고 (다른 게) 나와요.**
- 🔥 **오버레이 네트워크는 약간 개념이 다르다.** (버추얼도) 맞아요, 로지컬도 맞아요, 컨셉추얼도 맞아요. 근데 그게 **오버(위에) 중복되어서 뭔가 얹혀져 있다는 느낌**의 포인트가 좀 (있어요).

### ⭐ Virtual Circuit — 두 가지 개념
**버추얼 서킷**이라고 이야기하면 — 이 말은 **서킷 네트워크처럼 동작을 하는데 가짜다**는 얘기입니다. **진짜는 패킷이다.** 이거 (구분하는 게) 필요합니다.

## 11. ⭐ Virtual Connection — 그리고 MPLS 다시 보기

그래서 이거를 조금 더 (구분)해서, 영어를 조금 더 도입해 나가면 ⭐ **virtual connection**이라고 하는 용어가 나올 수 있어요. (잘 안 들림) … **커넥션 오리엔티드 서비스**(와 연결되죠).

💬 알고 나면 굉장히 쉬운 이야기인데, 비슷한 이야기를 자꾸 반복하니까 조금 (헷갈리)거나 할 수 있죠. 그래서 지금 (정리)하는 게 좋은 (거예요).

### ⭐ Virtual Circuit은 어디서 나오나 → MPLS (레이어 2.5)
virtual circuit가 뒤에서 (어디서) 나오냐 하면 — 아까 (앞에서) **MPLS** 그거 이야기하면서 제가 뭐라고 그랬냐면, "이거 대부분의 엔지니어들은 **레이어 2.5**입니다" 라고 이야기를 했어요. 그렇게 이야기를 한 이유가 —
- **처음에 세팅할 때는 L3**를 쓰고,
- **(데이터 전달할) 때는 L2 스위치(처럼)** 동작합니다.

그럼 이 이야기도 (같이) 봐.
- 처음에 **라우팅**을 할 때는 — 어느 쪽으로 가도 돼요? 이렇게 가도 되고, 이렇게 가도 되고, 이렇게 가도 되고. 그래서 데스티네이션으로 가는 라우팅을 찾을 때는 **레이어 3에서 찾아, 전형적인 패킷 베이스처럼 찾아.**
- 그리고 그 여러 개의 경로들 중에 **하나를 지정**을 딱 하는 순간 — **데이터는 이 길만 거쳐서 가는 거예요.**
- 그럼 이게 뭐야? 🔥 **버추얼 서킷 방식.**
- 이렇게 보낼 때 뭘 본다고? **레이어 2만 본다고.** (L2가 동작한다는 이야기가 많아요.) 데이터 보낼 때는 (L3를) 동작 안 시키겠다는 이야기하고 똑같은데, 처음에 L3에서 동작할 때 **대표적인 프로토콜**이 있어요. (→ 뒤에 나옴)

### 🔥 Virtual Connection = L4의 커넥션 오리엔티드 + L3에 대해선 "가짜"
**virtual connection**은 뭐냐면 — **Connection Oriented Service**, 혹시 여러분들 이거 기억나는지 모르겠어요? Connection Oriented Service를 어떻게 이야기를 했느냐 — **COS나 Circuit Based Network**.
- 서비스를 (하기 전에) 네트워크한테 **시그널링을 보낸다.**
- ⭐ **시그널링이 뭐? 데이터 전송하기 바로 직전까지 이루어지는 네트워크와 디바이스 간의 모든 행위가 시그널링으로 이루어진다.** 이렇게 정의를 했어요.

그러면 **connection oriented** — connection oriented라 하면 데이터를 (송신)에서부터 (수신)까지 전달하는데,
- **경로 지정을 포함해서,**
- sender와 destination에 "**데이터 줄 거니까 받을 준비해.**" "**OK, 내가 데이터 받을 준비 끝났어.**" 라고 하는 행위 —
- 🔥 **여기까지가 딱 끝나는 게 시그널링**입니다.

사람이 이해하기 가장 쉬운 것 중 하나가 — **전화번호 꾹꾹 눌러 주세요.** (잘 안 들림) … 수화기를 딱 들고, 또는 **통화 버튼을 딱 누르는 순간 모든 시그널링이 끝났습니다.** "**여보세요**" 라고 하는 말이 **데이터** 왔다 갔다 하는 겁니다.

그러면 시그널링 행위라고 이야기하는 그 행위는 무엇을 하고 있는 중이냐면 —
⭐ **데이터의 전달 경로를 설정하고 + 송신자와 수신자 간에 "데이터 주고받을 거니까 준비해"라고 하는 커넥션까지를 포함합니다.**

여기에서 이 **커넥션**이라고 하는 것 — 시그널링을 주고받는데, **"버추얼"이라고 하는 것이 딱 붙어 있어.**
- 버추얼이 빠지면 어떻게 한다고 그랬냐면 — 시그널링 주고받고, 데이터가 딱 와서 **정해진 경로로 보내는** 게 됐는데,
- ⭐ **버추얼 커넥션은 레이어 4에 있습니다.** 레이어 4에 있으니까, 얘는 OSI 7 레이어의 구조를 보면 **레이어 4와 레이어 3가 동작**을 합니다.
- 🔥 **그런데 이 "버추얼"은 누구를 대상으로 버추얼이냐면 — 레이어 3를 대상으로 버추얼입니다.**

그러니까 —
- (송신)하고 (수신)이 "데이터 주고받을 거니까 (준비해), 신호 받으면 (응답해)" 이렇게 하는 거는 **해.**
- 근데 **실제로 데이터가 전달되는 경로를 세팅해서 하나의 패스만 결정**을 하느냐 하면 — **그건 안 한다**니까요.
- 🔥 **하나의 데이터 패스로 보낸 것처럼 하고 커넥션 잡는 행위를 취하는 것.**
- **실제로 데이터는 플랫 구조에서 니가 (알아서) 가요.**

차이 나죠?
- 아까(버추얼 서킷)는 **시그널링에서 데이터 패스를 결정**하는 건데,
- 지금(버추얼 커넥션)은 **시그널링을 하고, 데이터 패스는 — 데이터 보낼 때는 니가 알아서** 보내면 (돼요). → **패킷 베이스의 전형적인 모습**입니다.

## 12. 🔥 정리 — "어느 레이어 이야기인지"를 보면 쉽다

(정리하면)
- **서킷 네트워크**에 가까운 조합 → **서킷 네트워크 / 버추얼 서킷**
- **버추얼 커넥션** 네트워크 → (패킷 베이스)
- 아, 용어가 비슷한데 — 🔥 **요것도 핵심 내용을 잘 기억해 보겠습니다.**

🔥 **레이어 2·3 상관에서 이야기할 때 버추얼이 들어가는 경우(= Virtual Circuit, MPLS)와, 레이어 3·4 이야기할 때 버추얼이 들어가는 경우(= Virtual Connection)가 다르다. 레이어를 생각하고 컨셉을 잘 잡으면 비교적 쉽다.**

## 📌 10/13 ① 핵심 요약

| 개념 | 정리 |
|---|---|
| 공지 | 🔥 **프로젝트 계획서 — 다음 주 화요일까지** / "찾아봐요" 한 내용 찾아보면 추가 점수 |
| ⭐ MPLS·VPN | L2와 L3 사이 → **처음 세팅은 L3, 이후 전달은 L2** → **레이어 2.5** |
| 🔥 공부법 | 졸업 전까지 5번 반복된다 / **"무슨 의미인가"를 꼭 짚고, 모르면 자료 찾아 읽기** |
| ⭐ 라우팅 | **길 찾기** = 출발지→목적지 데이터를 **어떤 길로** 보낼까 / 🔥 **구조적인 동작에 해당하는 용어** |
| ⭐ 계층(위계) 구조 | **Hierarchical** — 예: **전화번호** / 경로가 **기본적으로 1개** / 얘가 얘한테 매달림 → 🔥 **이동통신망(2G~6G)** 에서 계속 사용 |
| ⭐ 평면 구조 | **Flat** — 예: **IP address(인터넷)** / 경로가 **여러 개 (일의적이지 않음)** → **스위치(라우터)가 결정** |
| 🔥 대표성 | 전화번호·IP는 **대표 예시**일 뿐, 꼭 그것만 계층/평면인 건 아님 |
| 💬 스위치 네트워크 그림 | 기존 토폴로지 어디에도 해당 안 될 수 있음 → **평면 구조** / 장비 개발은 ~2015년쯤 완료, R&D 거의 없음 / 🔥 그래도 **KT 등 취업하면 그 장비를 만진다** |
| ⭐ Switched Network | **Circuit(=CBN)** / **Packet(=PBN)** / **Message** — 🔥 메시지 스위칭은 **사이즈가 정해지지 않아 거의 사라짐 → 패킷으로 통일** |
| ⭐ Packet Switched | = **Datagram** 방식 + **Virtual Circuit** 방식 / 🔥 흔히 PBN이라 하면 **데이터그램** |
| 🔥 자르는 곳 | 파일을 **처음 자르는 곳은 L4 → Segment** / L3 → **Packet** (다시 쪼개질 수 있음) / L2 → **Frame** (다시 쪼개짐·재조립) / **페이로드 크기는 L2·3·4가 다 다를 수 있다** |
| ⭐ Circuit vs Packet | Circuit: **정해진 데이터 패스** / Packet: **패킷마다 임의의 경로** (1·2·3·4번 패킷 경로가 다 다름) |
| ⭐ 왜 경로가 다르나 | 라우터가 **그 시점에 가장 좋은 경로**(라우팅 알고리즘·성능) 선택 → 🔥 **데이터그램 = 패킷 단위 라우팅** |
| 🔥 Virtual Circuit | **진짜는 패킷인데, 가짜로 서킷처럼** — 패킷 단위로 동작하지만 **경로는 하나로 고정** → 🔥 **시그널링 필요** (Connection Oriented) / 예: **MPLS** (L3로 경로 찾고, 지정 후엔 L2만 보고 전달) |
| ⭐ Virtual Circuit 2개념 | ① 실제로 **경로를 고정** ② **연결된 것처럼 보이기만** 하고 실제 연결은 없음 |
| 🔥 Overlay | Physical **Bus**(1,2,3,4) 위에 "1→2→3→4→1로 전달" 프로토콜 → **Logical Ring** / 🔥 **원래 토폴로지 위에 하나 더 얹혀 쳐 놓은 느낌** (Virtual·Logical·Conceptual과 뉘앙스 차이) |
| ⭐ 시그널링 (복습) | **데이터 전송 직전까지 네트워크–디바이스 간 모든 행위** = 경로 설정 + "받을 준비해/준비 끝" / 예: 통화 버튼 누르는 순간 시그널링 끝, "여보세요"부터 데이터 |
| 🔥 Virtual Connection | **L4**의 Connection Oriented — 송수신자 간 **커넥션은 잡지만**, 🔥 **L3에 대해선 버추얼** → 경로는 고정 안 함, **패킷이 알아서** 감 (전형적 PBN) |
| 🔥 핵심 구분 | **L2·3에서의 Virtual(Virtual Circuit) ≠ L3·4에서의 Virtual(Virtual Connection)** → **레이어를 생각하고 컨셉을 잡으면 쉽다** |
