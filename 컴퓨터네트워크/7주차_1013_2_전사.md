## 4. ⭐ 사람 목소리 = 0 ~ 4kHz

이제 바로 — 이것부터 이야기를 해야 해요. (잘 안 들림) … (이건) 이야기해도 되고 안 해도 되고.

- 0에서 4kHz로 단적으로는 (말하지만) — **0Hz는 없겠죠.**
- 0에서 4kHz까지의 **주파수 대역**을 (차지)합니다. 사람의 목소리가 주파수 대역을 (차지)한다는 게 무슨 말일까요? 여러분이 관심 있는 사람들은 사운드를 잡고 (분석) 해 보세요.

### 💬 목소리는 지문처럼 — 피치(Pitch)
**사람의 목소리는 전부 다 고유성이 있습니다.** 그래서 목소리를 **지문처럼** 쓸 수 있습니다.
지문처럼 사용하는 것의 핵심이 뭐냐면 ⭐ **피치(Pitch)** 라고 하는 게 있어요.
- 사람의 목소리의 **스펙트럼**을 분석을 해 보면 **고유한 주파수, 레조넌스(공진)** 가 몇 개가 (나옵)니다.
- 그 몇 가지의 주파수가 섞여서 그 사람의 목소리의 특성을 만드는 겁니다.
- 🔥 **그 몇 개의 고유한 주파수가 있는데, 그 간격을 피치라고 이야기합니다.**

그 주파수가 — 우리가 2학년 (잘 안 들림) … 여러분들 **삼각함수**에서 cos과 cos을 곱하면 **cos(ω1 + ω2)**, 두 개의 주파수가 **합해진 성분도 나오고 빼진 성분도** 나오죠. (그렇게) 사람의 목소리가 나오죠.
- 어떤 사람은 주파수가 높고 어떤 사람은 주파수가 낮다.
- 대체적으로 **남자들은 주파수가 낮은 편**이고, 저주파수 대의 주파수 성분이 나오죠. 피치 (차이가 있다).

### 🔥 4kHz + 4kHz = 8kHz? — 옛날 아날로그 방식, 지금은 아님
**4kHz는 음성 사운드의 (대역)**에 해당하는 (것이고), (다중화) 기계에서 이렇게 합쳐집니다.

(슬라이드를 보면) **아날로그 신호 두 개가 그냥 산술적으로 합쳐진** 것처럼 보이죠. 4kHz짜리 두 개를 합쳤으니까 **8kHz**의 대역처럼 보인다.
→ "4kHz 두 개 합하면 8kHz가 되냐, 무슨 말도 안 되는 소리를 하는지…"

실제로는 아까 이야기했던 것처럼 이 방식이 지금 안 쓰여? 쓰여요, 지금도 있어요. 그래서 그냥 (내는) 건데 — 🔥 **단편적으로 이렇게 외우지 말고**:
- **옛날 아날로그 통신 시절에는 두 개 합쳐서 8kHz 맞아요.**
- 🔥 **지금은 절대로 이렇게 안 합니다.** 이게 **디지털로 바뀌고요**, 디지털로 바뀌어 압축이 되어서 다시 (멀티플렉)싱이 되기 때문에, 여기 얼마가 나올지는 (방식)에 따라서 (다릅니다). 지금 전화망도 그러니까 참고하십시오.

## 5. 🔥 T1 라인 = 1.544 Mbps — 어디서 나오나

이때 이야기하는 게 뭐냐면 ⭐ **T1 라인**이라고 하는 게 있어요. **1.544 Mbps.**
- 여기에 무슨 단위인가요? **데이터 전송 속도**라고 합니다.
- **bit per second** — 초당 몇 개의 비트를 보내냐. **1.544 × 10⁶** 개의 비트를 보내는 전송 라인입니다.
- 우리가 흔히 이렇게 이야기하는 거야. "**T1급**으로…" T1급이 대략 1.544. 🔥 **이거는 엔지니어를 한 사람은 다 알아요.**

이게 지금 어디에서 이야기해요? **circuit switch 네트워크**에서 이야기하죠. 패킷 베이스 네트워크에서 쓸까 안 쓸까? 🔥 **전송 쪽에 근무하는 사람은 지금도 쓰고 있습니다.** 지금 6G 국가 프로젝트 하고 있다고 했죠. 그 사람들 모이면 여전히 (써요). 근데 이제 한 번도 들어 본 적이 없다 — "뭐 T1? 이런 시합 있는데 뭐야?" 이런 이야기 나오죠. (잘 안 들림)

### 💬 4×8 스위치
**4×8 스위치** — (입력) 4개, (출력) 8개 / 8개, 4개. 이렇게 쓰는 것도 있습니다. 이 스위치의 내부 구조를 (보면) … (잘 안 들림)

### ⭐ 계산: 4kHz → 64kbps → ×24 → T1
이거를 간단하게 여기에 — **4kHz를 데이터화시키면 얼마가 나온다고 했어요?** 혹시 기억하시는 사람?

4kHz가 **아날로그 신호** 4kHz 그랬죠? 그러면 아날로그 신호를 디지털로 바꾸고 보면 (몇) Hz가 생성이 된다? 이쪽에 있는 (잘 안 들림) … 최대 대역이 4kHz죠. (그러면) **샘플링**을 —

🔥 **신호처리 시간에 배우고 있습니다. 나이퀴스트(Nyquist) 이론에 따라 최대 대역의 2배로 샘플링을 해야 합니다. → 8kHz로 샘플링을 해야 합니다.**
- **샘플 한 개당 8비트**를 쓰면,
- 1초에 **8k(샘플)를 8bit로 표현**하니까 → ⭐ **64kbps**
- 🔥 **보이스(음성)의 데이터 생성 속도는 Raw 데이터 64kbps.**
- ⭐ **64kbps를 24개 묶으면 → 얼마가 되냐 → 1.544 (Mbps)** 이런 식의 이야기입니다.

> 📝 (보충, 교재 기준) 64kbps × 24 = 1.536Mbps + 프레이밍 비트 8kbps = **1.544Mbps**

그래서 그냥 그렇게 알아 주세요.
- ⭐ **64kbps를 몇 개 묶어서 TDM을 해서 → T1**
- **T1을 몇 개 묶어서 → T2**
- **T2를 몇 개 묶어서 → T3**
- **T3를 몇 개 묶어서 → T4** 이렇게 한다.

전송 속도가 1.544 → (계속) 올라가겠죠. 그러면 **몇백 Mbps급**의 전송 속도가 만들어지고, 전송 선로가 **구리선**에서 **동축 케이블**, 그러다가 나중에 몇백 (Mbps)로 올라가면 **광 케이블**로 바뀌어 (가는), 그런 식의 (발전)이 따라옵니다.

### ⭐ T(북미) vs E(유럽) — 찾아보기
**T1, T2, T3, T4는 (북미) 스펙**들이 하는 것입니다.
- 여기에 8비트가 아니라 **7비트로 (샘플링/양자화)** 하는 경우 → **56kbps**로 데이터 생성해야겠죠. 이걸 몇 개 묶으면 1.544가 안 나올 거야.
- 그거를 ⭐ **E1, E2, E3, E4**라고 하는 게 있어요.
- 🔥 **T 계열을 북미 방식이라고 하고, E 계열을 유럽 방식이라고 해요. 이거는 한번 찾아보시겠습니다.**

(잘 안 들림) … 64k짜리를 몇 개 묶어서 (T1), T1을 몇 개 묶어서 몇 개를 묶어야 되냐? 🔥 **그걸 외우지는 않아도 되지만, 개념은 갖고 있어요.** (잘 안 들림)

### ⭐ 전송 속도가 다른 링크를 연결하면?
(그림 — 데이터 네트워크) 전송 속도를 계산해서 네트워크를 하고 있는 동안에 — (속도가 다른 링크들이) **다 이렇게 연결이 가능할까요?**
- (예) 1.544하고 (그보다 작은) 1.368 두 개를 연결하면 — **1.368이 1.544로 건너갈 때는 100% 수용**이 되죠.
- **1.544가 1.368로 (가려고) 하면?** → **손실이 일어나겠죠.** 그죠? 다 (연결을) 못 해서 불안해서.
- 그럼 **한쪽을 다른 쪽의 최대치보다 더 크게** 만들어요. 더 크게 만들면 여기 **리소스의 비효율**이 되죠.
- 이거를 엔지니어들이 또 막 고민을 해. 나중에 이제 공부 다 하면 그 단계까지 (가요).

지금은 아까도 이야기했지만 — 이런 쪽에 엔지니어 리크루트가 떨어지는 게, 현재는 서킷 스위치 네트워크가 (줄어들고) 패킷 베이스 네트워크로 바뀌었으면서도 **전송 라인은 또 (이) 스펙을 고집하는** (영역)이 있습니다. (잘 안 들림)

그래서 이런 정도까지만 제가 가능해 보겠습니다. 🔥 **이런 용어들이 있다고 하는 것은 기억을 해 주시면 좋고요.**

## 6. 🔥 QoS vs QoE

(다음은) 서킷 스위치 네트워크에서의 (지연)이라고 이야기합니다. 요거 이야기하기 전에 — (잘 안 들림)

**QoS**라는 것은 — (잘 안 들림) … ⭐ **Quality of Service**라고 이야기를 하는 걸로 정리를 합니다.

이 이야기를 제가 지금 왜 하냐 — 얼마 전에 (잘 안 들림) … 이런 이야기입니다.

### ⭐ 음질 평가 — MOS 방식
(음성 품질을) 측정할 때 (**MOS**)라는 방식으로까지 넣어요. 측정 방식을 어떻게 하면 돼요?
- **100명이 있다면 100명한테 폰을 줘요.** 귀에 대 봐.
- **1점부터 5점** — 제일 좋은 질은 몇 점? (5점)
- (그래서 평균 내 보니) **"이 사운드의 질은 3.5"** — 이렇게 평가를 합니다.

이렇게 평가를 하는 건 누가 평가를 하는 거예요? → **바로 유저(사용자)** 가 됩니다.

(그러면) **3.5의 질을 유지하기 위해서** — (잘 안 들림) … ⚠️ (예: "최소한 200Mbps", "2만 가입자의 (교환) 스위치" — 숫자 일부 불확실) … 아까 이야기했던 **T4** 이런 식으로 스펙을 준다.
→ 이런 스펙의 네트워크를 구현한다. 🔥 **이렇게 (기술 스펙으로) 이야기를 할 때는 QoS라는 용어를 써요.**

그런데 **사운드 질 3.5라고 하는 것을 유저(사용자)가 정의**했다고 이야기를 할 때, 사용자의 정의를 뭐라고 하냐 하면 — **경험(Experience)**, 사용자가 느끼는 정도에 해당하는 —
- ⭐ **사용자가 느끼는 질을 따질 때는 QoE (Quality of Experience)** 라는 용어를 쓰고요,
- ⭐ **Technical Specification(기술적인 사양)**, 기술적인 어떤 질의 정도를 이야기하는데 — 흔히 **bps, 레이턴시(latency), SN Ratio(Signal to Noise Ratio)** 이런 거 이야기를 할 때 → **QoS (Quality of Service)** 라는 용어를 써.

🔥 **그래서 Technical Specification에 해당하는 QoS, User Experience에 해당하는 QoE라는 용어를 다 기억해 두시고요.**

### 🔥 네트워크에서의 QoS 두 가지 = Loss, Delay
QoS를 **네트워크 사이드**에서 지금 공부하고 있는 중이니까 — 네트워크에서, 학부 등에서 이야기하는 ⭐ **QoS는 두 가지밖에 없다. 하나가 Loss, 하나가 Delay.**

둘 중에 하나 — (잘 안 들림) … (Loss는) **딜레이가 무한대**에 해당하는 특수한 (경우)로 보면 이것도 (딜레이로) 볼 수 있겠죠. 그죠?

학부 과정에서 네트워크 사이드에서 QoS를 보는 두 가지는 대부분 **딜레이, 로스** 이 두 가지에 대해서 집중적으로 이야기를 할 텐데,
- **하드웨어** 쪽으로 가면 **bandwidth(대역폭)** — 이거는 왜 그러냐면 **파워 소모, 에너지 소모** 때문에 대역이 있습니다. 이게 더 붙여지는데,
- **네트워크에서는 에너지 쪽은 (잘) 안 봐요.**

3. ⭐ 다시 커넥션 쪽에서 **디스커넥션(해제)** 을 한다. (→ **시그널링**)

## 9. 🔥 평면 구조 라우팅의 문제 — 패킷 순서가 뒤바뀐다

(그림 — 1, 2, 3, 4번 패킷이 각자 다른 길로 가서 도착) … **그런 상황이 발생합니다.** 🔥 **이거는 기본입니다.** (3학년 데이터통신) 이런 이야기들을 제가 집중적으로 많이 할 거예요.

네트워크가 어떤 상황을 만들어 내면 —
- ⭐ **하이어라키컬 구조, 커넥션 오리엔티드 서비스에서는 이런 문제가 생길까요? 안 생기죠.** 왜냐하면 **정해진 길이 하나밖에 없기** 때문에 1, 2, 3, 4로 보내면 1번이 그 길을 따라서 (가고), 2번이 가야 되고, 그 다음 3번이 따라가야 되고 — 🔥 **이런 상황은 절대로 생기지 않습니다.**
- 🔥 **근데 플랫 구조에서의 라우팅 방식은 저 문제가 생기고 있습니다.**

**문제가 뭐였죠?**
1. **네트워크의 토폴로지가 플랫**한 거야.
2. 두 번째는 **라우터가 패킷 단위로** (라우팅하고) 있어. 1번·2번·3번·4번을 동일한 구조로 묶어서 보내는 것이 아니라 —
   - 1번 전송. 2번은 1번과 관계없이 **인디펜던트하게** 전송.
   - 1번·2번 관계없이 3번은 3번대로 전송…
3. → **도착할 때 순서가 (뒤바뀌지).** 극단적으로 패킷이 중간에 **로스**가 되는 것도 (있어요).

### ⭐ 레이어 3 = 로지컬 네트워크
어디에서 — 레이어 3단에서. **레이어 3는 뭐라 그랬죠? 로지컬**이라고 그랬죠.
🔥 **레이어 3는 하드웨어의 진짜 연결 유무가 아니라, IP 어드레스 단위처럼 보여지는 로지컬 네트워크입니다.** 이런 구조를 기능적으로 동작을 한다는 것입니다.

기능 수행을 이야기하다 보니까 (경로가) 제각각이기 때문에, 레이어 3의 기능으로 수신단에서 받고 보니까 **레이어 3에서 순서가 (바뀌어) 붙어** (있어요).

### 🔥 누가 해결해야 할까? → 레이어 4
자, 그러면 이거를 **누가 해결을 해야 될까요?** 레이어 2가 해결이 될 수 있을까?

**보낼 때는요** —
- **레이어 4에서 세그먼트를 패킷화하면서 패킷의 순서를 1, 2, 3, 4로 정했어요.**
- 보낼 때는요, 1번부터 레이어 2, 레이어 1을 거쳐서 보낸 거예요. 그 다음 2번을 레이어 2, 레이어 1을 거쳐서 보내고, 3번, 4번 순서로 보내.
- 많은 경로 상에서 순서가 (바뀌어서) 처리하는데 동작 시간이 달라서 — 그래서 도착하고 보니 **어디에서 본다**는 이야기예요?
  - 레이어 1에서 본다? 아니죠. 레이어 2다? 아니죠.
  - 🔥 **Peer 관계에 의해서 레이어 3에서 패킷의 1, 2, 3, 4를 따지니 — 어, 이게 순서가 바뀌었죠.**

**레이어 3가 해결을 해야 될 것 같죠? 근데 레이어 3에는 이 번호 붙인 적이 없어요.**
- (레이어 3는) **전달해 주는 겁니다.** (출발지)에서부터 (목적지)까지 데이터 전달했어야 하는 거예요. 1번 전달했지, 2번 전달했지, 3번 전달했지, 4번 전달했지. 전달했잖아. **나도 끝. 역할 끝.**

→ 🔥 **레이어 4로 올라가게 됩니다.**

레이어 4에 올라가면 — 아까 제가 잠깐 그 이야기를 했어요. 뭔 이야기? ⭐ **Virtual Connection**이라고 했어요.
- **버추얼 커넥션**이라고 이야기하고, 커넥션이 뭐라고요? **마치 커넥션을 잡으면 — 서킷 베이스처럼 동작하는 걸로 보여야** 됩니다.
- 그러면 서킷 베이스에서의 동작 — 데이터 (전송)할 때의 그 상황이 되어야 되는 게 아니라, ⭐ **순서 이런 게 제대로 맞는 것으로 (보여야 하는)** 관계예요.
- 그러니까 🔥 **이 순서의 재정렬을 — 레이어 4가 맡아서** 하는 거예요.

🔥 **그러니까 프로토콜이라고 이야기하는 것과 OSI 7 레이어의 기본적인 개념, 핵심 내용을 가히 엮으면 아주 기가 막히게 로지컬합니다. 굉장히 (논리)적이거든요.**
- 레이어 3가 통신할 때는 (순서를) 제대로 못 해요. 통신자의 입장에서는 순서를 맞춰서 말했는데, **레이어 3로 구성이 되어 있는 네트워크가 순서를 틀어 버려요.** 이건 **네트워크의 특성**이에요.
- 🔥 **그럼 이(레이어 3)의 부족함, 불편함 또는 단점에 해당하는 것들은 — 상위 레이어인 레이어 4가 보완(해결)해 주는 기능을 가져요.** (→ 6주차: "Lower Layer의 문제는 위 레이어가 해결")

### ⭐ 정리 — 데이터그램 / 패킷 스위치 네트워크
이런 것들이 이제 뭐냐 하면 —
- **데이터그램 방식이 데이터 보내는 방식**입니다. 데이터그램을 1, 2, 3, 4의 (패킷) 그룹으로 보내는 것입니다.
- 저 1번 한 개, 2번 한 개를 **패킷**이라고 하고, **패킷 단위로 서비스하면 패킷 스위치 네트워크**라고 하고, 데이터의 전달 측면에서 보면 데이터 전체적으로 이렇게 (보낸다).

## 10. ⭐ 스위치 vs 라우터 — 지금 R&D는 라우터 쪽

데이터 전달해 주는 장비 —
- ⭐ **서킷 베이스에서는 스위치**라고 얘기하고,
- ⭐ **패킷 베이스에서는 라우터**라고 얘기하는 게 있어요.

- **스위치**는 아까 제가 (이 정도) 선에서 끝냈습니다. 🔥 **지금 R&D를 하는 건 별로 없어요.** 용어를 익히는 선으로.
- 🔥 **라우터 쪽은 지금도 활발하게 R&D가 되고** 있고, 여러분들이 이런 거 하고 이쪽으로 (간다면) 이런 상황들은 기본적으로 알고 있어야 됩니다.

### 🔥 라우터의 기본 구조
**라우터**라고 이야기하면 —
⭐ **라우팅 알고리즘, 라우팅 테이블, 패킷 포워딩, 디폴트 라우트** — 이런 거 **기본적인 구조**를 가지고 있어야 됩니다. 기본적인 동작의 (메커니즘).

**그중에 가장 중요한 게 뭐예요? → 라우팅.**
- ⭐ **라우팅 알고리즘의 결과가 라우팅 테이블**에 있습니다.
- 기본적으로 라우팅 테이블 가지고 있으면, 단적으로 (매번) 라우팅 알고리즘 안 돌고 (테이블을 봐요).
- 🔥 **라우팅 테이블에 내가 찾는 길이 없어? 그러면 디폴트 라우트로 던진다**고 그러죠.

(예 — 슬라이드의 라우팅 테이블) **데스티네이션 어드레스가 1232(…)로 되어 있으면 1번(포트)으로 내보내** — 이런 식으로 라우팅 테이블이 만들어집니다.

그럼 이 (주소)들 — "1232, 4150, 9130…" 이라고 하는 것은(→ 어느 포트로 보낼지는) **어떻게 결정이 되냐?** 🔥 **이게 바로 라우팅 알고리즘의 결과**인데, 이건 또 예습 — 나중에 (L3) 이야기 때 또 이런 이야기가 나올 거예요. **이건 예습.**

## 11. ⭐ IP 주소 = Network ID + Host ID

(잘 안 들림) … IP 어드레스임에도 불구하고 — 🔥 **IP 어드레스는 두 가지로 쪼개집니다.** IP 어드레스 한 개는 어떤 성분 요소를 가지고 있느냐 하면 —
- ⭐ **네트워크 ID**로 쓸 수 있는 (부분)과,
- ⭐ **호스트 ID**(로 쓸 수 있는 부분), **2가지로 나뉘지.**

그럼 이 **네트워크 ID**라고 이야기를 하는 것은 — 우리가 **DNS** 이야기할 때 **도메인 네임** 이야기하는 게 있죠, 그죠? 그 도메인 네임의 **대표성을 띠는 공통 (부분)**, 네트워크가 있죠.

(예) ⭐ **충북대학교는 210.125.151.147**이라고 하는 (주소)를 볼 수가 있는데 —
- (잘 안 들림) … 실제 (호스트 부분)은 아예 **PC(호스트) 하나 — 147번**을 (가리켜요).
- **150에 있는 147도 아니고, 137에 있는 147도 아니고, 151에 있는 147.**
- 그럼 요건(**210.125.151**)은? → (네트워크 부분)
- 🔥 **요거를 네트워크 ID, 호스트 ID라고 표현하는 표현식**(입니다).

### ⭐ IP = Internetwork Protocol / 라우터는 네트워크 ID만 본다
**IP가 뭐예요?** — **인터네트워크 프로토콜**이라고 했지요.
- 🔥 **네트워크와 네트워크를 연결해 주는 것을 인터넷이라고 한다고** 합니다.
- **사이에 뭐가 들어갔다고요?** 사이에 들어가는 거 → **라우터.**
- 라우터는 (그냥) 이 네트워크하고 이 네트워크 연결하고, 이 네트워크하고 이 네트워크 연결해 주는 게 아니라, 그 사이에 **L3 IP**가 올라가 있어.
- 그럼 이건 뭘 하면 되냐면 — "이 네트워크의 ID가 몇 번이냐? 이 네트워크는 IP들에서 몇 번 쓰고 있다?" 🔥 **이거 몇 번 쓰고 있다만 알려 주면, 이쪽으로 (보내면 돼요).** 각각의 호스트 ID까지는 (라우터가 볼 필요가 없어요).

아까 이야기했던 겁니다.
- (목적지가) **210.125.151**(.147), (출발지가) **10.23.40**(…) — 그러면 🔥 **210.125.151까지만 보고 전달해.**
- 여기 (충북대 네트워크로) 들어오고 나서 **147 찾으면** 됩니다. 개념이 그런 식으로 됩니다.

그래서 이 그림을 보면 **destination address 몇 번에 포트 몇 번** 이렇게 되어 있는데, 한 개 더 — 이 address는 뭐라고? **네트워크에 관한 address**입니다. 그래서 **네트워크 ID**로서 (라우팅 테이블에) 네트워크 ID가 있어요.

### 🔥 Longest (Prefix) First
(네트워크) ID가 어떤 거는 **여덟 비트**, 어떤 거는 **열 비트**, 어떤 거는 **스물네 비트**, 어떤 거는 (스물) 비트인데 — 찾을 때는 뭐 찾냐 하면,
🔥 **가장 긴 어드레스부터 먼저 찾는다. 나에게 없으면 그 다음, 그 다음, 그 다음 이렇게 찾는다.** 이런 거 **Longest First** 방식이라고 (해요). **가장 긴 거 먼저 찾는다.**
> 📝 (보충) 정식 용어는 **Longest Prefix Match(최장 접두사 일치)** 예요.

| ⭐ MUX / DEMUX | 링크 3개 → 하나로 **다중화(Multiplexed)** → 다시 **역다중화(De-multiplexed)** |

| 🔥 SS7 | 서킷망의 시그널링 체계 — **지금도 쓰이고 앞으로도 당분간 쓰인다** → 4-2 무선통신망공학 |
| ⭐ 자원 점유 | 전화번호 누르는 순간 **리소스 예약·확보** → 다른 사람 못 씀 |
| ⭐ 목소리 대역 | **0~4kHz** / 🔥 **피치** = 목소리 고유 주파수(공진)들 사이의 간격 → 목소리는 지문처럼 쓸 수 있다 |
| 🔥 4k+4k=8k? | **옛날 아날로그 시절엔 맞음** / 🔥 **지금은 디지털 변환·압축 후 다중화라 절대 이렇게 안 함** — 단편적으로 외우지 말 것 |
| 🔥 T1 = 1.544Mbps | 🔥 **지금도 T1·T2·T3를 쓴다** (전송 속도의 기준) / 면접: "**들어 본 적 있고, 전송 속도의 기준점 이야기**"까지만 답해도 OK |
| 🔥 64kbps 계산 | 4kHz → **나이퀴스트: 2배 = 8kHz 샘플링** × **8bit** = **64kbps** (음성 Raw 데이터) → **×24 → T1(1.544Mbps)** → T1 묶어 T2 → T3 → T4 (구리선 → 동축 → 광) |
| ⭐ T vs E | **T = 북미**, **E = 유럽** (7bit면 56kbps) → 🔥 **찾아보기** / 몇 개 묶는지 외울 필요는 없지만 **개념은 알 것** |
| ⭐ 속도 다른 링크 | 작은 쪽 → 큰 쪽은 100% 수용 / 큰 쪽 → 작은 쪽은 **손실** → 한쪽을 키우면 **리소스 비효율** |
| 🔥 QoS vs QoE | **QoS** = 기술 사양(bps, latency, SNR) / **QoE** = 사용자가 느끼는 질 (예: **MOS** — 100명이 1~5점 평가 → 3.5) |
| 🔥 네트워크 QoS | **Loss, Delay 두 가지뿐** (Loss = Delay 무한대인 특수한 경우) / 하드웨어 쪽은 **bandwidth**(전력·에너지) |
| ⭐ 서킷 Delay | **커넥션 설정(시그널링) → 데이터 전송 → 디스커넥션** = 토탈 딜레이 |
| ⭐ 데이터그램 | 패킷 스위치망에서 패킷이 **Fixed or Variable Size**로 나뉨 (대표: **IPv4**) |
| 🔥 패킷 크기 | **IP(L3) = 20~65,536바이트 가변(약 64K)** / L2는 종류마다 다름: **ATM 53바이트 고정, 이더넷 1500바이트** → **잘라야 함 = Fragmentation** (이번 학기 범위는 아님, 다시 나옴) |
| 🔥 순서 뒤바뀜 | **계층 구조·커넥션 오리엔티드에선 절대 안 생김** / **플랫 구조 + 패킷 단위 독립 라우팅** → 도착 순서가 바뀜, 로스도 |
| ⭐ L3 = 로지컬 | 하드웨어 연결이 아니라 **IP 주소 단위로 보이는 로지컬 네트워크** |
| 🔥 순서는 누가? | 순서 번호는 **L4가 세그먼트 → 패킷화할 때** 붙임 / L3는 "전달했으니 역할 끝" → 🔥 **L4(Virtual Connection)가 재정렬** = **하위 레이어의 단점은 상위 레이어가 보완** |
| ⭐ 스위치 vs 라우터 | **CBN = 스위치** (R&D 거의 끝) / **PBN = 라우터** (🔥 **지금도 활발한 R&D**) |
| 🔥 라우터 기본 구조 | **라우팅 알고리즘 → 결과가 라우팅 테이블** → **패킷 포워딩** / 테이블에 없으면 🔥 **디폴트 라우트**로 |
| 🔥 IP 주소 | **Network ID + Host ID** — 예: **충북대 210.125.151.147** → 라우터는 🔥 **210.125.151(네트워크)까지만 보고 전달**, 들어와서 **147(호스트)** 찾음 |
| ⭐ IP | **Internetwork Protocol** — 네트워크와 네트워크를 연결, **사이에 라우터** |
| 🔥 Longest First | 네트워크 ID 길이가 제각각(8·10·24비트…) → **가장 긴 것부터 먼저 찾는다** (= **Longest Prefix Match**) |
