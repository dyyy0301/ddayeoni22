# 연구 주제 탐색 에이전트 PoC (디렉터-이론 논쟁 루프)

## 원래 의도

기존 연구 기획은 "문제 정의" 단계에서부터 연구자 개인의 편향(몇 년간
쌓아온 전공/방법론/논문에 대한 익숙함)에 갇히기 쉽다. 이 PoC는 연구자의
배경과 무관한 완전히 낯선 도메인에서, 그 도메인의 교과서적 근거 자료를
분석하며 새로운 연구 주제를 뽑아낼 수 있는지, 그리고 그 결과물이 진짜
쓸만한지(생뚱맞은 이식이 아닌지)를 검증하기 위한 PoC다.

지금 확인하려는 건 **"이 구조로 신박한 아이디어를 실제로 찾아낼 수
있는가"**이며, 특정 도메인(PNT 등)에 대한 검증이 목적이 아니다.
`examples/`의 입력은 그 구조를 시험해보기 위한 예시일 뿐이다.

## 전체 파이프라인

```
[Phase -1] 도메인 확보 (target_domain/grounding_text가 입력에 없을 때만)
   무작위 추첨(콜드 스타트) — 사람이 도메인을 정해주지 않으면 이 경로가 유일하다.
   OECD 학문분류(42개 세부분야)에서 random.choice()로 진짜 무작위 추첨
   → 그 안의 구체 이론을 실제 검색으로 좁혀 grounding_text 확보
   (random_domain.py)
        │
[Phase 0] 디렉터 — 시드 생성 (3~4개, 두 모드를 섞음)
   ├─ 딴지형(Devil's Advocate): 근거 강박 해제 / 순진한 가정 타격 /
   │    극한 스트레스 테스트 (예시일 뿐, 자유 확장 가능)
   └─ 호기심천국형(Naive Curiosity): "이건 왜 하필 이렇게 되지?" 식
        순수한 질문. 뉴턴의 사과처럼, 별도 소스 없이 grounding_text 안의
        구체적 디테일 하나를 그냥 신기해하는 것으로 충분
        │
[Phase 1] 이론 ↔ 디렉터 논쟁 루프 (시드마다 독립적으로 전부 실행)
   이론(원 도메인 편향 최대, 정설로만 반박/답변) <-> 디렉터(웬만하면 안 물러남)
        │
        ├─ 이론이 물러남           -> passed
        ├─ 디렉터가 물러남         -> discarded  (여기서 폐기, 더 진행 안 됨)
        └─ max_rounds(기본 20) 도달 -> deadlocked
        │  (passed / deadlocked만 아래로 전파)
        │
[Phase 3] 외부 자문 (실제 검색)
   Abstraction(final_claim, 공용 컴포넌트 재사용)
   → Cross-domain Structural Search(abstraction별로 실제 검색,
     원 도메인 근처 결과만 나오면 다른 abstraction으로 재검색)
   → 후보 3개(상위 학문 계열 다르게, 클리셰 비유 배제) 중 하나 확정
   → Knowledge Transfer(그 전공자로 페르소나 전환, 다시 검색해서 방법론 이식)
        │
[Phase 3.5] 이식 검증 — 원 도메인 상식과 충돌하는가
   외부자문의 이식 제안을 새로운 claim으로 취급해 같은 이론<->디렉터
   논쟁 루프에 한 번 더 태움 (run_debate 재사용, 최대 6라운드).
   이론은 여전히 원 도메인 전문가일 뿐 — "타 분야 이론이 옳은가"가 아니라
   "이 이식이 원 도메인이 아는 제약과 충돌하는가"만 심사한다.
        │
        ├─ 디렉터가 이식을 방어 못 함(discarded) -> 실무 게이트 자체를 건너뜀
        └─ 살아남음(passed/deadlocked, 보통 더 좁혀진 형태로) -> 다음 단계
        │
[Phase 4] 실무·보조 게이트
   feasibility 스키마(data/benchmark/implementation_time/evaluation_metric/
   domain_dependency/risk)로 채점 → verdict: go | conditional | no-go
   go/conditional이면 실행계획(implementation_plan: toy_design/tools/
   milestones)까지 생성. no-go면 계획은 안 짬(null)
        │
        └─ verdict != no-go 인 것만 "최종 문서화"
```

## 왜 이렇게 구성했는가

- **디렉터의 두 모드**: 처음엔 "딴지형" 3개 전술만 있었는데, 이건 예시일
  뿐 강제 분류표가 아니다. 실제 통찰은 도발보다 순수한 호기심("이건 왜
  하필 이렇게 되지?")에서 시작하는 경우도 많아서(뉴턴의 사과), 딴지형과
  호기심천국형을 섞어 쓰게 했다. `tactic` 필드도 자유 텍스트로 열어서
  디렉터가 스스로 새 접근을 이름 붙여도 되게 했다.
- **이론 에이전트**: 도메인이 고정된다. 편향이 최대치로 걸려 있고, 기존
  이론/정설로만 반박·답변하며, 웬만하면 물러나지 않는다(낮은
  temperature). "말이 안 통하는" 상대가 있어야 논쟁이 아이디어를 실제로
  단련시킨다.
- **디렉터의 반박/재질문**: 역시 웬만하면 안 물러난다. 반박당하면 원래
  주장을 그대로 반복하지 않고 한 단계 더 구체화/조건화해서 되받아친다
  (높은 temperature). 정말 결정타를 맞았을 때만 concede하도록 해서,
  "무조건 버티기"로 실험이 무의미해지는 걸 막았다.
- **20회 임계값**: 합의도 항복도 안 나는 논쟁은 "쉽게 결론 나지 않을
  만큼 흥미로운 지점"이라는 신호로 보고, 폐기하지 않고 다음 단계로 넘긴다.
- **구조 추상화(Abstraction)를 별도 컴포넌트로 분리**: 원래는 외부 자문이
  프롬프트 안에서 "구조 추출 + 검색"을 한 호흡에 처리했다. 문제는 나쁜
  추상화가 나오면(원 도메인 티가 남아서 검색이 근처에서만 맴돎) 검색까지
  낭비된다는 것 — 실제로 "3D shape" 같은 단어가 남은 추상화로는
  컴퓨터비전 근처 결과만 나온다는 걸 실측했다. 그래서 Abstraction(서로
  다른 두 각도 생성)을 독립 함수로 떼어내, 외부 자문이 이걸 입력으로만
  받아 검색부터 시작하게 했다.
- **외부 자문**: 도메인을 미리 고정하지 않는다. 주어진 abstraction들로
  실제 검색 → 원 도메인과 상위 학문 계열이 다른 후보 3개(카오스이론·
  양자역학 같은 클리셰 비유는 검색 근거가 구체적이지 않으면 배제) → 확정
  → 그 전공자로 페르소나 전환 후 재검색해서 이식 제안. "이미 있는
  사례인지"는 LLM 내부 지식 추측이 아니라 `web_search_20250305`로 실제
  검색하게 했다.
- **이식 검증(신규)**: 외부 자문 혼자 검색→선택→제안을 다 하고 아무도
  되묻지 않으면, 표면적으로 그럴듯한 말장난 수준의 매칭도 통과할 위험이
  있다. 그렇다고 이론 에이전트한테 "타 분야 이론이 맞는가"를 물으면
  안 된다 — 이론은 원 도메인 전문가일 뿐 물류학·경제학 전문가가 아니라서
  답을 모른다. 대신 기존 이론<->디렉터 논쟁 루프를 그대로 재사용해서
  "이 이식이 원 도메인이 이미 아는 제약과 충돌하는가"만 심사하게 했다.
  실측 결과, 이 단계에서 화려한 이식이 훨씬 좁고 방어 가능한 형태로
  깎이는 걸 확인했다(예: "여러 벡터의 물리적 릴레이" → 핵막 수송
  메커니즘과 충돌해 폐기 → "다중 태그 활성화 타이밍 최적화"로 축소).
- **도메인 선택은 무작위 추첨만 쓴다**: "연구자 배경으로 도메인을
  추정해서 그것과 다른 분야를 스카우트"하는 구조도 시도해봤지만,
  연구자 배경 정보를 아예 안 받는 편이 구조가 단순하고, 이 PoC가 검증
  하려는 것("도메인 없이도 신박한 아이디어를 뽑아낼 수 있는가")과도 더
  맞는다고 판단해 걷어냈다. 대신 LLM한테 "무작위 도메인 하나 골라봐"라고
  시키면 학습 데이터에서 자주 본 클리셰(양자역학, 카오스이론)로 수렴하는
  걸 실측으로 확인했기 때문에, 진짜 외부 무작위 소스(OECD Fields of
  Science 2007, 42개 세부분야)에서 `random.choice()`로 뽑게 했다
  (`random_domain.py`).
- **실무·보조**: 아이디어의 학술적 가치는 안 본다. feasibility 스키마로만
  채점한다. go/conditional이면 바로 착수 가능한 toy model 설계·실제
  라이브러리 이름·3단계 마일스톤까지 뽑아준다 — 평가로 끝내지 않고
  "그래서 뭘 하면 되는지"까지 한 번에 나오게 했다. no-go면 계획 자체를
  안 짠다(시간 낭비니까).
- **선별적 문서화**: discarded, 이식 검증 실패, 실무 no-go로 걸러진
  항목은 "내부 트레이스"에만 남기고 공식 산출물에는 포함하지 않는다.

## 실행

```bash
pip install -r requirements.txt

# 실제 Claude 호출 (API 키 필요, web_search 도구 포함)
export ANTHROPIC_API_KEY=sk-...
python3 run_poc.py examples/new_domain_exploration.json -o report.md

# API 키 없이 파이프라인 구조만 검증 (mock 응답, 라운드 상한을 줄여서 빠르게 확인)
python3 run_poc.py examples/new_domain_exploration.json --mock --max-rounds 4
```

mock 모드는 결정적으로 짜여 있어(`llm.py` 주석 참고) 매번 같은 결과가
나온다 — 4개 시드(딴지 3 + 호기심 1) 중 하나는 논쟁만 통과(passed) 후
이식 검증까지 통과해 문서화되고, 하나는 논쟁 단계에서 디렉터가 물러나
폐기(discarded)되고, 나머지 둘은 논쟁에서 deadlock난 뒤 이식 검증에서
디렉터가 못 버텨 실무 게이트 자체를 건너뛴다. 세 갈래 결과(문서화 O /
논쟁에서 폐기 / 이식 검증에서 폐기)를 전부 재현하도록 설계되어 있다.

## 실행 결과 예시 (실제 검색 기반, 수동 재현)

API 키 없이도 이 세션 자체의 웹서치로 파이프라인을 손으로 여러 번
끝까지 돌려봤다. 예를 들어 콜드 스타트로 뽑힌 "Health biotechnology"
→ "유전자 치료 벡터 전달"에서, 디렉터의 "왜 벡터 하나가 전 구간을
전담해야 하는가"라는 딴지가 논쟁을 통과하고, 외부 자문이 물류공학의
"릴레이 트럭킹"을 이식안으로 제안했지만, 이식 검증 단계에서 "핵막
수송은 어떤 벡터가 넘겨줬는지 신경 안 쓴다"는 반박에 걸려 "여러 벡터의
릴레이"라는 원안은 폐기되고 "다중 태그 활성화 타이밍 최적화"라는 더
좁고 방어 가능한 형태만 살아남았다 — 이식 검증 단계가 의도대로
과장된 매칭을 걸러낸다는 걸 확인했다.

## 파일 구성

- `prompts.py` - 디렉터(시드/재반박)·이론·Abstraction(공용)·외부자문·
  콜드스타트그라운딩·실무보조 6개 system prompt
- `random_domain.py` - 콜드 스타트용 무작위 도메인 추첨
  (OECD Fields of Science 2007, 6대 분야 42개 세부분야)
- `llm.py` - Anthropic API 호출 wrapper. `search=True`면 실제 API 모드에서
  `web_search_20250305` 도구를 붙임. mock 모드 포함 (분기 설명 주석 있음)
- `orchestrator.py` - 도메인 확보 → 시드 생성 → 논쟁 루프 → 이식 검증 →
  실무 게이트 → 선별적 문서화 전체 파이프라인
- `run_poc.py` - CLI 진입점 (`--max-rounds`로 라운드 상한 조정, `--mock`)
- `examples/new_domain_exploration.json` - 곤충 사회성 군집 이론을
  grounding으로 삼아 낯선 아이디어를 탐색 (도메인 지정)
- `examples/percolation_forest_fire.json` - 산불 확산의 침투 이론
  (percolation theory)에 붙인 두 번째 예시 (도메인 지정)
- `examples/true_cold_start.json` - target_domain/grounding_text가 없어서
  콜드 스타트(무작위 추첨)가 실행되는 예시

## 다음 단계 (미해결)

- 검색이 붙는 모든 단계(콜드스타트그라운딩/외부자문)를 실제
  `ANTHROPIC_API_KEY`로 자동 실행해본 적은 아직 없다 — 지금까지는 API 키
  없이 이 세션 자체의 웹서치로 손으로 재현해서 검증했다. 자동화된
  `run_poc.py` 경로의 실제 검색 품질은 아직 미검증.
- 디렉터의 시드 생성 자체에는 검색을 안 붙였다 — grounding_text가 이미
  검색으로 확보되니 필요성은 낮지만, 더 날카로운 반례를 위해 추가할
  수도 있다.
- 실제 API로 20라운드 논쟁 + 검색 2회(콜드스타트, 외부자문 — 이식검증은
  검색 없음) + 이식검증까지 여러 개 돌리면 비용/시간이 꽤 든다. 실험
  예산을 먼저 계산해볼 필요가 있다.
- "신박함"을 사람이 최종 판단해야 하는지, 외부 자문의 참신성 판단을
  정량 점수화할지는 아직 미정.
- 실무 게이트가 no-go로 걸러내는 실제 사례(구체적 예시)는 아직 안
  만들어봤다 — go/conditional 사례 위주로만 검증했다.
