## 4·5주차 (영상 강의) 힙 정렬 · 우선순위 큐 · 비비교 정렬

> 영상 강의로 대체 — 전사본 없음. 강의자료(Lecture 4, 5) + 10/6 복습 수업 내용 기준 정리

### 1. ⭐ 정렬 알고리즘의 두 가지 성질

**In-place (제자리 정렬)**
- **추가 메모리 공간 없이** 입력 배열 안에서 정렬 (변수용 상수 공간은 허용)
- 예: 버블·선택·삽입·퀵·힙 ✅ / 병합·계수·기수 ❌

**Stable (안정 정렬)**
- **같은 값을 가진 원소들의 상대적 순서가 정렬 후에도 유지**되는 것
- 같은 값이 없거나, 같은 값끼리 구분이 안 되면 상관 없음
- 🔥 **언제 중요?** 여러 키로 정렬할 때
  - (월로 정렬 → 연도로 정렬) 했을 때, stable해야 같은 연도 안에서 월 순서가 유지됨
  - (이름으로 정렬 → 성으로 정렬)도 마찬가지
- 예: **버블은 stable** — 인접한 두 값이 같으면 교환하지 않으므로 순서 유지
- 💡 stable이 아님을 보이려면 **순서가 바뀌는 반례 하나**만 찾으면 됨

### 2. ⭐ 힙 (Heap)
- **완전 이진 트리(complete binary tree)** + **힙 속성(heap property)**
  - 완전 이진 트리: 마지막 레벨을 빼고 꽉 차 있고, 마지막 레벨은 **왼쪽부터** 채워짐
  - **Max-heap**: 부모 ≥ 자식 (A[parent(i)] ≥ A[i]) → **루트가 최댓값**
  - **Min-heap**: 부모 ≤ 자식 → **루트가 최솟값**
  - (하나의 힙은 둘 중 하나의 속성만 따름)
- **배열로 표현**: 루트는 A[1], 레벨 순서로 저장 → parent(i) = ⌊i/2⌋, left(i) = 2i, right(i) = 2i+1
- n개 원소 힙의 **높이 = ⌊lg n⌋**
  - 높이 h인 힙의 원소 수: 최소 **2ʰ**, 최대 **2ʰ⁺¹ − 1** → 2ʰ ≤ n < 2ʰ⁺¹ → h = ⌊lg n⌋

| 연산 | 하는 일 | 복잡도 |
|---|---|---|
| **MAX-HEAPIFY(A, i)** | A[i]를 아래로 내려보내(floating down) i를 루트로 하는 서브트리가 max-heap 되게 함 | **O(lg n)** (트리 높이) |
| **BUILD-MAX-HEAP(A)** | 배열을 max-heap으로. **⌊n/2⌋부터 1까지 거꾸로(bottom-up)** MAX-HEAPIFY 호출 (n/2+1 ~ n은 리프라 이미 힙) | 단순 계산 O(n lg n) → **tight하게 O(n)** |

- BUILD-MAX-HEAP이 O(n)인 이유: 대부분의 노드는 높이가 낮음. 높이 h인 노드는 최대 ⌈n/2ʰ⁺¹⌉개, 각 비용 O(h) → Σ h/2ʰ 가 상수로 수렴 → **O(n)**

### 3. ⭐ 힙 정렬 (Heap Sort)
1. **BUILD-MAX-HEAP** (오름차순이면 max-heap, 내림차순이면 min-heap)
2. **루트(최댓값) A[1] ↔ 마지막 노드 A[i] 교환** → 최댓값이 제자리에 확정
3. 힙 크기를 1 줄이고(마지막 노드 잘라냄) **MAX-HEAPIFY(A, 1)** 로 힙 복구
4. 2~3 반복

- 복잡도: BUILD O(n) + (n−1)번 × HEAPIFY O(lg n) = **O(n lg n)** (Best/Avg/Worst 모두)
- **In-place ✅ / Stable ❌**

🔥 **왜 루트를 "마지막 노드"와 바꾸나?**
- 큰 자식을 계속 위로 올리면 → **완전 이진 트리가 깨짐**
- 마지막 노드를 빈 루트 자리에 그냥 올리면 → 힙 속성이 깨질 수 있음 (→ 그래서 HEAPIFY)
- 교환 방식은 **① 완전 이진 트리 유지 ② 힙 속성 유지(HEAPIFY로) ③ 추가 메모리 없음(in-place)** 세 가지를 동시에 달성

🔥 **왜 리프를 바로 빼지 않고 루트를 빼나?** (10/13 수업)
- 루트만이 최댓값(최솟값)으로 **보장**됨. 리프끼리(형제끼리)는 정렬돼 있지 않고, 다른 레벨의 노드보다 클 수도 있음

### 4. 우선순위 큐 (Priority Queue)
- 일반 큐: **FIFO** (먼저 들어온 게 먼저 나감)
- 우선순위 큐: **우선순위가 높은 원소가 먼저** 나감 → 보통 **힙**으로 구현
- 활용: CPU 스케줄링, 허프만 코딩, **다익스트라**(최단 경로), **프림**(최소 신장 트리), k번째 작은 원소 찾기

| 연산 (max-heap 기반) | 방법 | 복잡도 |
|---|---|---|
| Get Maximum | 루트 반환 | **O(1)** |
| Extract Max | 루트 꺼내고 마지막 노드 올린 뒤 MAX-HEAPIFY (힙 정렬과 같은 과정) | **O(lg n)** |
| Increase Key | 값을 키운 뒤 **부모와 비교하며 위로** 교환 | **O(lg n)** |
| Insert | 새 리프 추가 후 Increase Key | **O(lg n)** |

### 5. ⭐ 비교 기반 정렬의 한계
- 🔥 **정리: 모든 비교 기반 정렬은 최악의 경우 Ω(n lg n)번 비교가 필요**
- → 힙 정렬, 병합 정렬은 **점근적으로 최적인** 비교 정렬
- → O(n)으로 정렬하려면 **비교를 하지 않는 방법**이 필요 → 계수·기수 정렬

### 6. ⭐ 계수 정렬 (Counting Sort)
- 핵심 아이디어: **x보다 작은(같은) 원소가 몇 개인지 알면 x의 위치를 알 수 있음** (7개가 작으면 8번째 자리)
- 배열: A(입력), **B(출력)**, **C(개수 저장, 0~k)** → 추가 공간 필요 → **in-place ❌**

1. C를 0으로 초기화
2. 각 값의 **개수** 세기 → C[i] = i의 개수
3. **누적합** → C[i] = i **이하**인 원소 개수
4. 🔥 A를 **뒤에서부터** 보면서 B[C[A[j]]] = A[j], 그리고 C[A[j]]−− → **stable ✅**

**예 (강의자료): A = [2, 5, 3, 0, 2, 3, 0, 3]**
- 개수 C = [2, 0, 2, 3, 0, 1] (0~5) → 누적 C = [2, 2, 4, 7, 7, 8]
- 뒤에서부터: 3 → B[7], 0 → B[2], 3 → B[6], 2 → B[4], 0 → B[1], 3 → B[5], 5 → B[8], 2 → B[3]
- B = [0, 0, 2, 2, 3, 3, 3, 5]

- 복잡도: **O(n + k)** (k = 값의 범위) → k = O(n)이면 **O(n)**
- ⚠️ **단점**: 값 범위 k가 n보다 훨씬 크면 메모리 낭비 (예: A = <3, 1000, 1, 2, 4> → n=5인데 C 크기 1001, 대부분 0)
  → **k가 n에 비해 작을 때만** 효율적, 그래서 일반적으로는 잘 안 씀

### 7. ⭐ 기수 정렬 (Radix Sort)
- **자릿수별로** 정렬 — **가장 낮은 자릿수(일의 자리)부터** 높은 자릿수로
- 🔥 각 자릿수 정렬은 반드시 **stable한 정렬**로! → 안 그러면 앞서 정렬한 낮은 자릿수 순서가 깨짐
- 각 자릿수 정렬에 **계수 정렬** 사용 (숫자는 0~9, k = 10이라 효율적)
- 복잡도: **O(d(n + k))** (d = 자릿수) → d가 상수, k = O(n)이면 **O(n)**
- 장점: 선형 시간, stable, 정수·문자열 대량 정렬에 효율적
- 단점: **정수·문자열 같은 특정 데이터만 가능 (실수 불가)**, 추가 메모리 필요

**예: A = <170, 45, 75, 90, 802, 24, 2, 66>** → 최대 3자리이므로 3번 반복 (일 → 십 → 백)
