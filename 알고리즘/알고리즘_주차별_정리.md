## 2주차 ① (9/8) 알고리즘 정의 · 정렬 · 버블/선택 정렬 · 성능 분석

### 1. 알고리즘이란?
**어떤 작업을 수행하기 위한 유한한 명령어들의 집합**

⭐ **알고리즘의 5가지 요구조건**

| 조건 | 의미 |
|---|---|
| **입력 (Input)** | 0개 이상의 입력 (없어도 됨) |
| **출력 (Output)** | 1개 이상의 결과가 나와야 함 |
| **명확성 (Definiteness)** | 각 명령이 모호하지 않아야 함 → "25도 이상이면 꺼라" ⭕ / "좀 더우면 꺼라" ❌ |
| **유한성 (Finiteness)** | 유한한 단계 후 반드시 종료 |
| **효과성 (Effectiveness)** | 불필요한 것 없이 실행 가능해야 함 |

### 2. 정렬(Sorting)
- n개의 원소를 **특정 순서(오름차순/내림차순)로 재배치**하는 것
- 활용: 특정 값 탐색, 최댓값/최솟값 찾기(정렬돼 있으면 맨 앞/맨 뒤만 보면 됨), 중복 제거·빈도 찾기, 은행 거래내역 날짜/금액순 조회
- 데이터가 커질수록(1억, 1조 개) **O(n²) vs O(n log n)** 차이가 엄청나게 벌어짐 → 효율적 정렬이 중요

⭐ **정렬 알고리즘 분류**

| 비교 기반 (Comparison-based) | | 비비교 기반 (Non-comparison) |
|---|---|---|
| 버블 · 선택 · 삽입 | 병합 · 퀵 · 힙 | 계수(Counting) · 기수(Radix) |
| **O(n²)** | **O(n log n)** | **O(n)** (특수한 상황) |

- 비비교 기반: 값끼리 비교하지 않음. 계수 정렬은 "1이 몇 개, 2가 몇 개" 개수를 셈 / 기수 정렬은 자릿수 기준
- 중간고사까지는 정렬 알고리즘을 다양한 관점에서 분석

### 3. 버블 정렬 (Bubble Sort)
⭐ **인접한 두 원소를 비교해서 순서가 틀리면 교환(swap)** 하는 과정을 반복
- 한 패스(pass)가 끝나면 **가장 큰 값이 맨 뒤로** 확정됨
- 이름 유래: 원소가 거품처럼 하나씩 올라가는 모습
- 구현: 이중 for문 (바깥: 패스 반복, 안쪽: 인접 원소 비교)

```
5 2 4 6 1 3  → 5↔2 swap → 2 5 4 6 1 3 → 5↔4 swap → 2 4 5 6 1 3
→ 5,6 그대로 → 6↔1 swap → 6↔3 swap → 2 4 5 1 3 [6]  ← 1회차 끝, 6 확정
```

### 4. 선택 정렬 (Selection Sort)
⭐ **정렬 안 된 부분에서 가장 작은 값을 선택해서 맨 앞(정렬된 부분)으로 보냄** 을 반복
- 가장 큰 값을 골라 맨 뒤로 보내도 같은 원리
- 구현: 이중 for문 (바깥: 위치 선택, 안쪽: 최솟값 탐색)

```
5 2 4 6 1 3 → 최솟값 1 찾음 → 1과 5 교환 → [1] 2 4 6 5 3
→ 나머지에서 최솟값 2 → [1 2] 4 6 5 3 → ...
```

> 💬 "버블이 좋을까 선택이 좋을까?" → 상황마다 다르다. 그래서 **객관적으로 비교할 기준 = 성능 분석**이 필요함

### 5. 알고리즘 평가 기준
1. **정확성** – 정렬이 제대로 됐는가
2. **효율성** – 얼마나 빨리 / 메모리를 적게 쓰는가 ← **이 수업의 초점**
3. **가독성** – 협업 관점에서 남이 읽을 수 있는 코드인가

⭐ **성능 측정 vs 성능 분석**

| | 성능 측정 (Performance Measurement) | 성능 분석 (Performance Analysis) |
|---|---|---|
| 방법 | 실제 컴퓨터로 실행해 시간 측정 | 복잡도(연산 횟수)를 수학적으로 분석 |
| 특징 | **기계 의존적** (machine-dependent) | **기계 독립적** (machine-independent) |
| 필요한 것 | 컴퓨터 | 종이와 펜 |

→ 이 수업은 **성능 분석(시간 복잡도)** 에 초점

### 6. 시간 복잡도 (Time Complexity)
⭐ **입력 크기 n에 대해 알고리즘이 실행하는 기본 연산(명령어)의 총 횟수** (실제 수행 시간 ❌)
- 세는 연산: 사칙연산·나머지·올림/내림, 데이터 load/store/copy, 조건문·비교·반복

🔥 **for문 비교 횟수가 n+1인 이유**
`for (i=0; i<n; i++)` → i가 0~n-1일 때 n번 + **마지막에 i=n일 때 `i<n` 비교에서 빠져나오는 1번** = **n+1번**

- 리스트 합 구하기 예: 총합 = c₁n + c₂ 형태 → 상수 무시 → **O(n)**

⭐ **버블 정렬 연산 횟수**
비교 횟수 = (n-1) + (n-2) + … + 1 = **n(n-1)/2** → **O(n²)**

- 리스트 합 예제 상세 (강의자료): 대입 1회(c₁) + for 비교 **n+1**회(c₂) + 덧셈·대입 n회(c₃) + return 1회(c₄) → (c₂+c₃)n + c₁+c₂+c₄ = **O(n)**

🔥 **비교 분석 (1초에 10⁹ 연산 컴퓨터 기준)**

| n | n³ | 2ⁿ |
|---|---|---|
| 32 | 32 μs | 4.3 초 |
| 128 | 2 ms | 6.5 × 10²³ 년 |
| 512 | 0.1 초 | **2.5 × 10¹³⁹ 년** |

→ 증가 속도: **1 < log n < n < n log n < n² < n³ < 2ⁿ < n!**

### 7. 점근적 분석 (Asymptotic Analysis)
⭐ **n을 충분히 크게(→∞) 했을 때 알고리즘의 증가 추세**를 보는 것
- 데이터 크기 측면에서 알고리즘 간 비교가 쉬움 (논문에서도 기존 알고리즘과 복잡도 비교 필수)
- 수학 지식만 있으면 종이와 펜으로 분석 가능

## 2주차 ② (9/8) 점근적 표기법 (O, o, Ω, ω, Θ)

### ⭐ 5가지 표기법 한눈에 보기

| 표기 | 관계 | 의미 | g(n)은 f(n)의 … |
|---|---|---|---|
| **O** (Big-Oh) | f ≤ g | 최대 이 정도 (상한) | asymptotic **upper bound** |
| **o** (Little-oh) | f < g | 등호 없는, 여유 있는 상한 | not tight upper bound |
| **Ω** (Big-Omega) | f ≥ g | 최소 이 정도 (하한) | asymptotic **lower bound** |
| **ω** (Little-omega) | f > g | 등호 없는, 여유 있는 하한 | not tight lower bound |
| **Θ** (Big-Theta) | f = g | 위아래로 꽉 묶임 | asymptotic **tight bound** |

### 1. Big-O
> **O(g(n)) = { f(n) : 양의 상수 c, n₀가 존재하여 모든 n ≥ n₀에 대해 0 ≤ f(n) ≤ c·g(n) }**

🔥 증명법: 부등식 **f(n) ≤ c·g(n)** 을 만족하는 **(c, n₀) 쌍을 하나라도 찾으면** 끝. 답은 여러 개 가능.

**예제 1)** 7n + 3 = O(n)
- 7n + 3 ≤ cn → c = 8이면 n ≥ 3에서 성립 ✅ (c=10, n₀=1 등 다른 쌍도 가능)

**예제 2)** 3n + 1 = O(n²)
- 양변을 n²로 나누면 3/n + 1/n² ≤ c → c = 4, n₀ = 1 ✅
- ⚠️ **명제는 참이지만 의미가 없음!** "10초 걸리는 알고리즘을 '만 초보다는 덜 걸려'라고 말하는 것" → 너무 느슨한 상한
- → 이런 **tight하지 않은 상한**을 표현하려고 나온 게 **little-o**

### 2. Little-o
> **o(g(n)) = { f(n) : 모든 양의 상수 c > 0에 대해, n₀가 존재하여 n ≥ n₀이면 0 ≤ f(n) < c·g(n) }**

⭐ 극한으로 판정: **lim (n→∞) f(n)/g(n) = 0** 이면 f = o(g)

🔥 **Big-O vs little-o 차이**
- **Big-O**: (c, n₀) **하나라도** 찾으면 OK
- **little-o**: **모든 c**에 대해 성립해야 함 (반례 하나면 실패)
- 강의자료 예 (f(n) = 2n + 3):
  - f = O(n) ✅ 이지만 f ≠ o(n) ❌ → **asymptotically tight** (최고차항이 같으면 little-o 불가)
  - f = O(n²) 이고 f = o(n²) ✅ / f = O(n³) 이고 f = o(n³) ✅

### 3. Big-Ω
> **Ω(g(n)) = { f(n) : 양의 상수 c, n₀가 존재하여 n ≥ n₀이면 0 ≤ c·g(n) ≤ f(n) }**

- Big-O의 반대: "**최소 이것보다는 오래 걸린다**" (하한)
- 증명: **c·g(n) ≤ f(n)** 을 만족하는 (c, n₀) 찾기
- **예제)** 3n² + 4n + 1 = Ω(n): n으로 나누면 3n + 4 + 1/n ≥ c → c = 2, n ≥ 2 ✅ (참이지만 tight하지 않음)
- ⚠️ 너무 낮게 잡은 하한(예: n² 알고리즘에 Ω(1))도 참이지만 의미 없음 → "최소 10초 걸리는 걸 '1초보단 더 걸려'라고 하는 것" → **little-ω** 등장

### 4. Little-ω
> **ω(g(n)) = { f(n) : 모든 c > 0에 대해, n₀가 존재하여 n ≥ n₀이면 0 ≤ c·g(n) < f(n) }**

⭐ 극한으로 판정: **lim (n→∞) f(n)/g(n) = ∞**

- 강의자료 예 (f(n) = 2n³ + 3):
  - f = Ω(n) & f = ω(n) ✅ / f = Ω(n²) & f = ω(n²) ✅
  - f = Ω(n³) 이지만 f ≠ ω(n³) → **asymptotically tight**

### 5. Big-Θ
> **Θ(g(n)) = { f(n) : 양의 상수 c₁, c₂, n₀가 존재하여 n ≥ n₀이면 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) }**

⭐ **Θ = O 와 Ω 를 동시에 만족** → 두 부등식 각각의 상수를 찾으면 됨

**예제)** ½n² − 3n = Θ(n²)
- n²로 나누면: **c₁ ≤ 1/2 − 3/n ≤ c₂**
- 오른쪽: c₂ = 1/2, n ≥ 1 이면 성립
- 왼쪽: c₁ = 1/14, n ≥ 7 이면 성립
- 둘 다 찾았으므로 ✅ Θ(n²)

🔥 **Θ의 핵심: 다항식이면 최고차항만 보면 된다**
- f(n)이 다항식이면 Θ(최고차항). O와 Ω 모두 최고차항이 같을 때 성립하기 때문
- 예: 3n² + 5n + 2 = Θ(n²)
- **정리: f = Θ(g) ⇔ f = O(g) 이고 f = Ω(g)** (상한 + 하한 = tight bound)

### 6. 코드 보고 복잡도 바로 구하기 (Guidelines)

| 코드 구조 | 복잡도 |
|---|---|
| 단일 for문 (n번) | **O(n)** |
| 이중 중첩 for문 | **O(n²)** |
| 삼중 중첩 for문 | **O(n³)** |
| for문 + 이중 for문 연속 | O(n) + O(n²) → **O(n²)** (큰 쪽만) |
| if-else | 실행되는 분기 중 **큰 쪽** (ex. if는 상수, else에 for문 → O(n)) |

🔥 결국 **반복문이 몇 번 도는지**를 세면 된다

- **최댓값 찾기**: for문 1개 → **O(n)**
- **선택 정렬**: for문 2개 중첩 → **O(n²)**

### 7. 예제: 누적 평균(Prefix Average) 구하기
배열의 각 위치 i까지의 평균을 구하는 문제 (예: 5 → 5, 5+3 → 4, 5+3+1 → 3, …)

| 방법 | 구현 | 복잡도 |
|---|---|---|
| 단순 방법 | 이중 for문 (i까지 매번 다시 더함) → 내부 실행 횟수 1+2+…+n = n(n+1)/2 | **O(n²)** |
| 개선 방법 | 누적합 변수를 for문 1개 안에서 계속 갱신 | **O(n)** |

⭐ 같은 문제도 **이전 계산 결과를 저장해 재사용**하면 O(n²) → O(n)

## 2주차 ③ (9/10) 점근 표기법 증명 연습 · 성질

### 1. 복습
- **O**: f(n) ≤ c·g(n) 만족하는 (c, n₀) 찾기
- **Ω**: c·g(n) ≤ f(n) 만족하는 (c, n₀) 찾기
- **Θ**: 둘 다 찾기 (c₁, c₂, n₀)
- 🔥 **시험에 이런 증명 문제가 몇 개 나옴** → 꼭 연습

### 2. 증명 연습 문제

**Q1) 2ⁿ⁺¹ = O(2ⁿ) ?** → ✅ 참
- 2ⁿ⁺¹ = 2·2ⁿ ≤ c·2ⁿ → 양변을 2ⁿ(항상 양수)로 나누면 **c ≥ 2**
- c = 2, n₀ = 1 이면 성립

**Q2) 2²ⁿ = O(2ⁿ) ?** → ❌ 거짓
- 2²ⁿ = 2ⁿ·2ⁿ ≤ c·2ⁿ → 양변을 2ⁿ로 나누면 **2ⁿ ≤ c**
- 2ⁿ은 지수적으로 계속 커지므로 **어떤 상수 c로도 막을 수 없음** → 거짓

🔥 **결론: 만족하는 (c, n₀)가 존재하면 참, 존재하지 않음을 보이면 거짓**

### 3. ⭐ 점근 표기법의 성질

| 성질 | 내용 | 성립하는 표기 |
|---|---|---|
| **추이성 (Transitivity)** | f = O(g), g = O(h) ⇒ f = O(h) (삼단논법) | **O, o, Ω, ω, Θ 모두** |
| **반사성 (Reflexivity)** | f = O(f) (자기 자신) | **O, Ω, Θ 만** |
| **대칭성 (Symmetry)** | f = Θ(g) ⇔ g = Θ(f) | **Θ 만** |
| **전치 대칭성 (Transpose Symmetry)** | f = O(g) ⇔ g = Ω(f) / f = o(g) ⇔ g = ω(f) | **(O, Ω) 쌍, (o, ω) 쌍** |

🔥 **왜 o, ω는 반사성이 안 될까?**
- 자기 자신과 비교하면 최고차항이 같아서 **f = f (등호)** 가 생김
- o, ω는 **등호 없는 엄격한 부등호**(<, >)라서 성립 불가

### 4. 연습: max(f(n), g(n)) = Θ(f(n) + g(n)) 증명 (f, g는 양수 함수)
- **Ω 쪽 (하한)**: 두 함수의 평균 (f+g)/2 ≤ max(f, g) → **c₁ = 1/2**
- **O 쪽 (상한)**: max(f, g) ≤ f + g (f가 크든 g가 크든, 오른쪽엔 나머지 양수가 더해짐) → **c₂ = 1** (2, 3, … 도 가능)
- 둘 다 성립 → ✅ Θ(f + g)

### 5. ⚠️ 모든 함수가 비교 가능한 건 아니다
- 실수는 1 < 2처럼 항상 대소 비교 가능하지만, **함수는 점근적으로 비교 불가능한 경우가 있음**
- 예 (강의자료 Exercise 4): f(n) = n, g(n) = n^(1 + sin n) (그 밖에 h(n) = n + sin n 도 제시)
  - sin n이 -1 ~ 1로 진동 → g(n)이 n⁰ ~ n² 사이를 왔다 갔다
  - 어떤 구간에선 g > f, 어떤 구간에선 g < f → **f ≠ O(g) 이고 f ≠ Ω(g)**
- 실제 알고리즘에선 거의 없음. "이런 경우도 있다" 정도로 기억

## 3주차 ① (9/15) 삽입 정렬 · 분석 유형 · 분할정복 · 병합 정렬

### 1. 삽입 정렬 (Insertion Sort)
⭐ **정렬 안 된 부분에서 key 하나를 꺼내, 정렬된 부분의 알맞은 위치에 삽입**
- 카드 게임에서 손에 든 카드를 정리하는 방식과 같음
- 배열은 **정렬된 부분 / 정렬 안 된 부분**으로 나뉨

```
Step0: 5 2 4 6 1 3
Step1: key=2 → 2 5 | 4 6 1 3
Step2: key=4 → 2 4 5 | 6 1 3
Step3: key=6 → 2 4 5 6 | 1 3   (이미 제자리, 이동 없음)
Step4: key=1 → 1 2 4 5 6 | 3   (맨 앞까지 이동)
Step5: key=3 → 1 2 3 4 5 6
```

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):      # n-1번 반복
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:  # key보다 큰 값들을 한 칸씩 뒤로
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key                 # 빈 자리에 key 삽입
```

**연습 문제 (강의자료 p.17, 오름차순)**

| step | 배열 |
|---|---|
| 1 | 7 4 3 6 8 1 2 |
| 2 | **4 7** 3 6 8 1 2 |
| 3 | **3 4 7** 6 8 1 2 |
| 4 | **3 4 6 7** 8 1 2 |
| 5 | **3 4 6 7 8** 1 2 |
| 6 | **1 3 4 6 7 8** 2 |
| 7 | **1 2 3 4 6 7 8** |

### 2. ⭐ 삽입 정렬 시간 복잡도
- 일반: for O(n) × while O(n) → **O(n²)**
- 🔥 **Best case (이미 정렬됨) → O(n)**
  - key를 넣을 자리를 찾으려 한 번 비교하면 이미 제자리 → while이 바로 끝남 (O(1))
  - for O(n) × while O(1) = **O(n)**

### 3. 🔥 Best case 비교: 버블 vs 선택 vs 삽입
- **버블 정렬 Best = O(n)**: 첫 패스에서 swap이 한 번도 없으면 이미 정렬된 것 → (n-1)번 비교 후 종료
- **선택 정렬 Best = O(n²)**: 최솟값인지 확인하려면 **이미 정렬돼 있어도 나머지 전부와 비교해야 함**
- **삽입 정렬 Best = O(n)**: 옆 원소와 한 번만 비교하면 끝

### 4. ⭐ 복잡도 분석의 3가지 유형

| 유형 | 입력 상황 | 비고 |
|---|---|---|
| **Best case** | 이미 (거의) 정렬된 입력 | 보통 의미 없지만 가끔 유용 |
| **Average case** | 모든 입력에 대한 평균 | 가장 많이 봄. 분석이 어려움 |
| **Worst case** | **역순으로 정렬된** 입력 | 다시 정렬하는 데 가장 오래 걸림 |

### 5. 삽입 정렬 정리
- **장점**: 구현이 쉽고 직관적 / **작은 데이터, 부분적으로 정렬된 데이터에 효율적**
- **활용**: 대용량에 강한 다른 정렬과 결합해서 사용
- 🔥 **과제 #1: 삽입 정렬 + 병합 정렬 결합** (병합 정렬 막바지 작은 구간을 삽입 정렬로 처리)

### 6. ⭐ 공간 복잡도 & In-place 정렬
- **공간 복잡도**: 입력 크기를 제외하고 알고리즘에 **추가로 필요한 메모리**
- **In-place 정렬**: 추가 메모리 없이 원래 배열 안에서 정렬 → 공간 복잡도 **O(1)**
- 버블 · 선택 · 삽입 정렬은 모두 **in-place**

| 정렬 | Best | Average | Worst | 공간 |
|---|---|---|---|---|
| 버블 | **O(n)** | O(n²) | O(n²) | O(1) |
| 선택 | **O(n²)** | O(n²) | O(n²) | O(1) |
| 삽입 | **O(n)** | O(n²) | O(n²) | O(1) |

### 7. 점화식 (Recurrence)
- 각 항이 **이전 항들의 함수로 표현**되는 식
  - aₙ = aₙ₋₁ + 1
  - n! = f(n) = n · f(n−1)
- **재귀 알고리즘의 시간 복잡도 분석**에 주로 사용 (팩토리얼, 피보나치, 하노이 탑 등)
- 예: factorial(5) = 5·factorial(4) = … = 5·4·3·2·1 = 120 → 몇 번 호출되는지 분석 가능

### 8. ⭐ 분할 정복 (Divide and Conquer)
큰 문제를 쪼개서 풀기 쉽게 만든 뒤 합치는 전략

1. **Divide (분할)**: 큰 문제를 작은 하위 문제들로 나눔
2. **Conquer (정복)**: 각 하위 문제를 **재귀적으로** 해결
3. **Combine (결합)**: 하위 문제의 해를 합쳐 원래 문제 해결

### 9. ⭐ 병합 정렬 (Merge Sort)
1. **Divide**: 배열을 반으로 나눔 → 원소가 **1개가 될 때까지** 반복
2. **Conquer**: 각 절반을 재귀적으로 병합 정렬
3. **Combine**: 정렬된 두 리스트를 하나로 **병합(merge)**

```
Divide:   [5 2 4 7 1 3 8 6]
          [5 2 4 7]   [1 3 8 6]
          [5 2] [4 7] [1 3] [8 6]
          [5][2][4][7][1][3][8][6]
Combine:  [2 5] [4 7] [1 3] [6 8]
          [2 4 5 7]   [1 3 6 8]
          [1 2 3 4 5 6 7 8]
```

```
MERGE-SORT(A, p, r)
1 if p < r
2    q = ⌊(p + r)/2⌋
3    MERGE-SORT(A, p, q)      → T(n/2)
4    MERGE-SORT(A, q+1, r)    → T(n/2)
5    MERGE(A, p, q, r)        → Θ(n)
```

🔥 **병합 정렬 점화식: T(n) = 2T(n/2) + Θ(n)**
- **Divide: Θ(1)** – 중간 인덱스만 계산
- **Conquer: 2T(n/2)** – 크기 n/2짜리 문제 2개
- **Combine: Θ(n)** – 크기 n/2짜리 정렬된 두 리스트 병합

### 10. 🔥 병합 정렬 복잡도 = O(n log n) (재귀 트리로 구하기)
T(n) = 2T(n/2) + cn 으로 놓고 트리를 그림

```
레벨 0:          cn                    → 합 cn   (노드 1개 = 2⁰)
레벨 1:      cn/2    cn/2              → 합 cn   (노드 2개 = 2¹)
레벨 2:   cn/4 cn/4 cn/4 cn/4          → 합 cn   (노드 4개 = 2²)
  ⋮
레벨 k:   c  c  c  …  c  (n개)          → 합 cn   (노드 n개 = 2ᵏ)
```

- ⭐ **각 레벨의 비용 합 = 항상 cn** (반으로 쪼개도 전체 데이터 개수 n은 그대로)
- ⭐ **레벨 수**: n/2ᵏ = 1 이 될 때까지 → n = 2ᵏ → **k = log₂n** (레벨은 log₂n + 1개)
- **전체 = cn × (log₂n + 1) = O(n log n)**

> 💡 이진 탐색처럼 **문제를 계속 반으로 쪼개서** n² → n log n 으로 줄인 것

🔥 **병합 정렬은 in-place가 아님!** → 쪼갠 배열들을 담을 **추가 메모리가 필요**

| 정렬 | Best | Average | Worst | In-place? |
|---|---|---|---|---|
| 병합 | O(n log n) | O(n log n) | O(n log n) | ❌ |

💡 점화식 T(n) = a·T(n/b) + f(n) 읽는 법
- **n/b**: 문제를 몇 등분하는지 (n/2 → 2등분, n/3 → 3등분)
- **a**: 그 조각을 몇 개 사용하는지
- a = b (예: 2T(n/2))이면 → 각 레벨 비용 합이 같음 → **(레벨 수) × (레벨당 비용)** 으로 계산

## 3주차 ② (9/15) 점화식 풀기: 치환법 · 재귀 트리

### 1. ⭐ 치환법 (Substitution Method)
1. **해를 추측(Guess)** 한다
2. **수학적 귀납법**으로 추측이 맞음을 증명한다

**예제)** T(n) = 2T(n/2) + n, 추측: T(n) = O(n²)
- T(n) ≤ cn² 라고 가정하고 대입
- T(n) ≤ 2·c(n/2)² + n = (c/2)n² + n ≤ cn² (c ≥ 2, n₀ ≥ 1이면 성립)
- ∴ O(n²) — ⚠️ **참이지만 좋은(tight) 상한이 아님!** 실제로는 n log n
- → **좋은 추측을 하는 게 중요** → 그 방법이 **재귀 트리**

### 2. ⭐ 재귀 트리 방법 (Recursion-Tree Method) — 좋은 해를 추측하는 방법
1. **재귀 트리를 그린다**
2. **각 레벨의 비용**을 계산한다
3. **레벨의 개수(트리 높이)** 를 계산한다
4. **모든 레벨의 비용을 합산**한다

> 💬 교수님: "치환법 증명보다는 **재귀 트리로 전체 복잡도를 도출하는 방법**을 잘 아는 게 중요하다"

### 3. 예제 1: T(n) = 2T(n/2) + n → **O(n log n)**
- 추측(재귀 트리): 레벨당 cn × 높이 log n → O(n log n)
- 귀납 증명: T(n) ≤ 2·c(n/2)·lg(n/2) + n = cn(lg n − lg 2) + n = cn lg n − cn + n **≤ cn lg n** (c ≥ 1)

### 4. 예제 2: T(n) = 3T(n/4) + Θ(n²) → **O(n²)**
T(n) = 3T(n/4) + cn² 로 놓음

```
레벨 0:   cn²                                 → cn²
레벨 1:   c(n/4)²  × 3개                       → (3/16) cn²
레벨 2:   c(n/16)² × 9개                       → (3/16)² cn²
  ⋮
레벨 i:   노드 3ⁱ개, 각 c(n/4ⁱ)²                 → (3/16)ⁱ cn²
```

- **높이**: n/4ᵏ = 1 → **k = log₄n**
- **마지막 레벨 노드 수**: 3^(log₄n) = **n^(log₄3)** (로그 밑 바꾸기 성질)
- **전체 합** = Σ (3/16)ⁱ cn² → 공비 3/16 < 1인 **등비수열**
  ≤ cn² · 1/(1 − 3/16) = (16/13)cn² → **O(n²)**

> ⚠️ 전사본에서는 공비가 "4분의 3"처럼 들리는데, 각 레벨 합은 3개 × (1/4)² = **3/16** 배씩 줄어드는 것이 맞음
> 🔥 핵심: **등비수열의 합**으로 처리 → 첫 항(최상위 레벨)이 지배 → O(n²)

### 5. 예제 3: T(n) = T(n/3) + T(2n/3) + cn → **Θ(n log n)** (불균형 트리)
- 한쪽은 n/3, 한쪽은 2n/3으로 쪼개짐 → **비대칭(불균형) 트리**
- 각 레벨 비용 합 ≤ cn
- ⭐ **경로마다 높이가 다름**
  - 가장 짧은 경로(계속 n/3): (1/3)ᵏn = 1 → **log₃n**
  - 가장 긴 경로(계속 2n/3): (2/3)ᵏn = 1 → **log_{3/2}n**

🔥 **불균형 트리에서 O / Ω / Θ 구하는 법**
- **O (상한)**: **가장 깊은 경로**(log_{3/2}n) 기준 → cn · log_{3/2}n → **O(n log n)**
- **Ω (하한)**: **가장 얕은 경로**(log₃n) 기준 → cn · log₃n → **Ω(n log n)**
- **Θ**: O와 Ω가 일치하면 → **Θ(n log n)**

> 🔥 교수님 스포: **시험에서 O를 물을지, Ω를 물을지, Θ를 물을지 번갈아 낸다** → 문제에서 무엇을 묻는지 꼭 확인! (그냥 "보여라"면 보통 O)

### 6. 3주차 정리
- **분할 정복**: 문제를 쪼개고 → 풀고 → 합침
- **재귀 트리**: 각 레벨 비용 × 레벨 수 → 전체 복잡도 **추측**
- **치환법**: 추측한 해를 **귀납법으로 증명**

## 3주차 ③ (9/17) 병합(Merge) 과정 · 병합+삽입 결합 · 마스터 정리 · 퀵 정렬

> 강의자료: Lecture 3-2. Divide and Conquer

### 1. 정렬된 두 배열 합치기 (MERGE) — Θ(n)
- 원래 배열 A, 왼쪽 절반 L, 오른쪽 절반 R
- ⭐ **인덱스 2개**(L의 i, R의 j)를 두고, L[i]와 R[j] 중 **작은 값을 A에 올리고 그 쪽 인덱스만 한 칸 이동**
- 각 원소를 한 번씩만 비교·복사하므로 **원소 개수만큼 = Θ(n)**
- (CLRS 방식: L, R 끝에 **∞(sentinel)** 를 넣어 한쪽이 먼저 끝나도 비교가 깨지지 않게 함)

```
L = [2 4 5 7 ∞]   R = [1 2 3 6 ∞]
1<2 → A에 1, j++ / 2≤2 → A에 2, i++ / 4>2 → A에 2, j++ / ... → A = [1 2 2 3 4 5 6 7]
```

### 2. ⭐ 병합 정렬 + 삽입 정렬 결합 (과제 #1의 핵심 아이디어)
- 병합 정렬은 원소가 **1개가 될 때까지** 쪼갬 → 그런데 아래로 내려갈수록 문제가 작고 쉬움
- 🔥 **아이디어**: 크기가 **K 이하**가 되면 더 쪼개지 말고 **삽입 정렬**로 처리
  - 이유: 삽입 정렬은 **작은 배열·거의 정렬된 배열에서 빠름** (Best O(n))
- 크기 K짜리 부분 배열이 **N/K개** 생김

| 단계 | Best | Worst |
|---|---|---|
| (1) 삽입 정렬 (N/K개 × 크기 K) | O(K · N/K) = **O(N)** | O(K² · N/K) = **O(NK)** |
| (2) 병합 (레벨 수 lg(N/K) × 레벨당 O(N)) | **O(N lg(N/K))** | **O(N lg(N/K))** |
| **전체** | N + N lg(N/K) = **O(N lg(N/K))** | NK + N lg(N/K) = **O(N lg(N/K))** |

- 레벨 수: 2ˡ = N/K → **l = lg(N/K)** (끝까지 안 내려가므로 lg N보다 작음)
- 비교: 병합 정렬 O(N lg N), 삽입 정렬 O(N²) → **K를 적당히 잡으면 더 효율적**
- ⚠️ 너무 작게 쪼개지 말 것 (Do not divide each subproblem too small)

🔥 **과제 #1** (다음 주 화요일 공지 예정)
1. 삽입 정렬 구현
2. 병합 정렬 구현
3. **병합 정렬 + 삽입 정렬 결합** 구현

### 3. 점화식 복습 (치환법 · 재귀 트리)
- 치환법: 해를 **추측** → **귀납법**으로 증명. 단, 추측이 너무 느슨하면(n인데 n²로 추측) 참이어도 의미 없음
- 그래서 **재귀 트리로 tight한 해를 추측** → 레벨당 비용 × 레벨 수
- 병합 정렬: T(n) = 2T(n/2) + n → 레벨당 cn × 높이 log₂n → **O(n log n)**

### 4. ⭐ 불균형 재귀 트리: T(n) = T(n/3) + T(2n/3) + cn
- **각 레벨 비용 = cn** (1/3 + 2/3 = 1 이라 쪼개도 합이 줄거나 늘지 않음)
  - 레벨 1: c(n/3) + c(2n/3) = cn
  - 레벨 2: c(n/9) + c(2n/9) + c(2n/9) + c(4n/9) = cn
- **높이가 경로마다 다름** (비대칭 삼각형)

| 구하는 것 | 볼 경로 | 높이 | 결과 |
|---|---|---|---|
| **O (상한)** | **가장 깊은 경로** (계속 2/3) — 일을 가장 많이 하는 쪽 | (2/3)ᵏn = 1 → **log_{3/2} n** | cn · log_{3/2} n = **O(n lg n)** |
| **Ω (하한)** | **가장 얕은 경로** (계속 1/3) — 가장 빨리 1에 도달 | (1/3)ᵏn = 1 → **log₃ n** | cn · log₃ n = **Ω(n lg n)** |
| **Θ** | O와 Ω가 같으므로 | | **Θ(n lg n)** |

- 귀납 증명(강의자료): T(n) ≤ d(n/3)lg(n/3) + d(2n/3)lg(2n/3) + cn = dn lg n − dn(lg3 − 2/3) + cn ≤ dn lg n (d ≥ c/(lg3 − 2/3))

> 🔥 교수님: "문제 내기가 싫다…" — 시험에서 **O / Ω / Θ 중 무엇을 구하라는지**에 따라 **깊은 쪽만 / 얕은 쪽만 / 양쪽 다** 계산해야 함!

**연습 문제 (강의자료 p.14, 직접 풀어보라고 하심)**
- Ex1: T(n) = T(n/2) + n³ 의 좋은 상한 추측 + 치환법 검증
- Ex2: T(n) = 4T(n/2) + n 의 좋은 상한 추측 + 치환법 검증
- Ex3: T(n) = T(n/3) + T(2n/3) + cn 이 **Ω(n lg n)** 임을 보여라 → **1/3쪽(얕은 경로) 트리**를 그릴 수 있어야 함

### 5. ⭐⭐ 마스터 정리 (Master Method) — 점화식의 "근의 공식"
재귀 트리를 안 그리고 바로 답을 구하는 **공식(cookbook)**

> **T(n) = a·T(n/b) + f(n)**
> - **a ≥ 1**: 하위 문제 개수 (쪼갠 덩어리를 몇 개 쓰나)
> - **b > 1**: 몇 분의 1로 줄어드나
> - **f(n)**: 분할 + 결합 비용 (현재 레벨에서 처리하는 일)

- 트리 높이 = **log_b n**
- 맨 아래(크기 1) 노드 개수 = a^(log_b n) = **n^(log_b a)**
- ⭐ 핵심: **f(n)** 과 **n^(log_b a)** 중 **누가 더 크냐**를 비교 → 큰 쪽이 복잡도를 결정

| Case | 비교 | 결과 |
|---|---|---|
| **1** | f(n) < n^(log_b a) — 정확히 f(n) = O(n^(log_b a − ε)) | **T(n) = Θ(n^(log_b a))** |
| **2** | f(n) = n^(log_b a) — f(n) = Θ(n^(log_b a)) | **T(n) = Θ(n^(log_b a) · lg n)** |
| **3** | f(n) > n^(log_b a) — f(n) = Ω(n^(log_b a + ε)) 이고 a·f(n/b) ≤ c·f(n) (c<1) | **T(n) = Θ(f(n))** |

💡 직관: 트리의 **아래쪽(리프)** 이 무거우면 Case 1, **위쪽(루트)** 이 무거우면 Case 3, **모든 레벨이 같으면** Case 2 (= 레벨당 비용 × 높이, 병합 정렬)

**강의자료 예제**

| 점화식 | a, b, f(n) | n^(log_b a) | Case | 답 |
|---|---|---|---|---|
| T(n) = 2T(n/2) + n | 2, 2, n | n | 2 (같음) | **Θ(n lg n)** |
| T(n) = T(n/2) + n³ | 1, 2, n³ | n⁰ = 1 | 3 (f가 큼) | **Θ(n³)** |
| T(n) = 4T(n/2) + n | 4, 2, n | n² | 1 (f가 작음) | **Θ(n²)** |

**연습 문제 (p.18) — 참고 풀이**
- Ex4: T(n) = 9T(n/3) + n → n^(log₃9) = n² > n → Case 1 → **Θ(n²)**
- Ex5: T(n) = T(2n/3) + 1 → a=1, b=3/2, n^(log 1) = 1 = f(n) → Case 2 → **Θ(lg n)**
- Ex6: T(n) = 3T(n/4) + n lg n → n^(log₄3) ≈ n^0.79 < n lg n → Case 3 → **Θ(n lg n)**

> ⚠️ 마스터 정리는 **T(n) = aT(n/b) + f(n) 꼴에서만** 쓸 수 있음. T(n/3) + T(2n/3)처럼 **재귀 항이 두 종류면 불가** → 재귀 트리 사용

🔥 **시험 채점 기준 (교수님 언급)**
- "복잡도를 구하시오"만 있으면 → 재귀 트리 / 마스터 정리 **아무 방법이나 OK**
- "재귀 트리를 이용해서" / "마스터 정리를 이용해서" 라고 지정되면 → **그 방법으로 풀어야 함**

### 6. ⭐ 퀵 정렬 (Quick Sort)
분할 정복 대표 알고리즘

| 단계 | 내용 |
|---|---|
| **Divide** | **피벗(pivot)** 기준으로 분할(Partition): **피벗 이하 → 왼쪽, 피벗보다 큼 → 오른쪽** |
| **Conquer** | 왼쪽·오른쪽 부분 배열에 **QuickSort 재귀 호출** (피벗 제외) |
| **Combine** | **필요 없음!** 분할할 때 이미 제자리로 보냈기 때문 (병합 정렬과의 차이 🔥) |

```
QUICKSORT(A, p, r)
1 if p < r
2    q = PARTITION(A, p, r)     // 피벗이 최종 위치 q에 놓임
3    QUICKSORT(A, p, q-1)
4    QUICKSORT(A, q+1, r)

PARTITION(A, p, r)
1 x = A[r]                      // 마지막 원소를 피벗으로
2 i = p - 1                     // i: 왼쪽(≤x) 영역의 끝
3 for j = p to r-1             // j: 검사 중인 원소
4    if A[j] ≤ x                // Case 2: 피벗 이하
5       i = i + 1
6       exchange A[i] with A[j] //   → 왼쪽 영역으로 보냄
7 exchange A[i+1] with A[r]     // 피벗을 두 영역 사이로
8 return i + 1
```
- A[j] > x (Case 1): 아무것도 안 하고 j만 증가 → 오른쪽 영역이 자연스럽게 늘어남
- **PARTITION 시간 복잡도 = Θ(n)**

🔥 **Partition 예제 (A = 2 8 7 1 3 5 6 4, 피벗 = 4)**

| 단계 | 비교 | 배열 (\| 는 ≤4 / >4 경계) |
|---|---|---|
| 1 | 2 ≤ 4 → 왼쪽 | 2 \| 8 7 1 3 5 6 [4] |
| 2 | 8 > 4 | 2 \| 8 7 1 3 5 6 [4] |
| 3 | 7 > 4 | 2 \| 8 7 1 3 5 6 [4] |
| 4 | 1 ≤ 4 → 8과 교환 | 2 1 \| 7 8 3 5 6 [4] |
| 5 | 3 ≤ 4 → 7과 교환 | 2 1 3 \| 8 7 5 6 [4] |
| 6 | 5 > 4 | 2 1 3 \| 8 7 5 6 [4] |
| 7 | 6 > 4 | 2 1 3 \| 8 7 5 6 [4] |
| 8 | 피벗을 경계로 (8과 교환) | 2 1 3 **4** 7 5 6 8 |

→ 피벗 4는 **최종 위치에 고정**, 이후 [2 1 3]과 [7 5 6 8]에 재귀

### 7. 🔥 퀵 정렬 복잡도 분석

| | 분할 모양 | 점화식 | 복잡도 |
|---|---|---|---|
| **Best (균형 분할)** | 반반으로 나뉨 (병합 정렬처럼) | T(n) = 2T(n/2) + Θ(n) | **Θ(n lg n)** |
| **Worst (불균형 분할)** | 한쪽은 0개, 한쪽은 n−1개 | T(n) = T(n−1) + Θ(n) | n + (n−1) + … = n(n+1)/2 = **Θ(n²)** |

⭐ **최악의 경우가 생기는 입력** (피벗을 맨 끝/맨 앞으로 잡을 때)
- **이미 정렬된 배열** (Example 7) → Θ(n²)
- **역순으로 정렬된 배열** → Θ(n²)
- **모든 원소가 같은 배열** (Example 8) → 전부 ≤ 피벗이라 한쪽으로 쏠림 → Θ(n²)

> ⚠️ 교수님 강조: "정렬돼 있으면 퀵 정렬이 최악이다"는 **절반만 맞음!**
> **피벗을 끝(맨 앞/맨 뒤)으로 잡았을 때** 정렬된 입력이 최악이다 — 라고 **정확하게** 써야 함.
> 피벗을 가운데로 잡으면 정렬된 배열은 오히려 반반으로 잘 나뉨.

### 8. ⭐ 최악의 경우 피하기: Randomized Quick Sort
- 퀵 정렬 성능은 **피벗 선택**에 달려 있음
- **랜덤 피벗**: A[p..r]에서 무작위로 하나 골라 A[r]과 교환한 뒤 PARTITION
  - 예: 데이터 100개 → 양 끝 값이 뽑힐 확률 2/100 → 평균적으로 꽤 균형 잡힌 분할 기대
  - 하지만 운이 나쁘면 여전히 끝 값이 뽑혀 Θ(n²) 가능

```
RANDOMIZED-PARTITION(A, p, r)
1 i = RANDOM(p, r)
2 exchange A[r] with A[i]
3 return PARTITION(A, p, r)
```

- **진짜 중앙값(median)** 이 가장 좋은 피벗이지만, 찾으려면 O(n) 스캔이 필요
- 🔥 **Median-of-3**: **무작위로 3개 뽑아 그중 중간값**을 피벗으로
  - 3개 중 가운데 값이므로 **배열 전체의 최솟값/최댓값은 절대 뽑히지 않음** → 극단적 쏠림 방지
  - 예: [8 2 5 3 7 9 1]에서 2, 5, 9 뽑음 → 중간값 **5**

### 9. 3주차 ③ 정리
- **MERGE**: 인덱스 두 개로 비교 → Θ(n)
- **병합 + 삽입 결합**: 크기 K 이하에서 삽입 정렬 → O(N lg(N/K)) — **과제 #1**
- **불균형 재귀 트리**: O는 깊은 쪽, Ω는 얕은 쪽, 둘이 같으면 Θ
- **마스터 정리**: f(n) vs n^(log_b a) 비교 → 3가지 Case
- **퀵 정렬**: 피벗 기준 분할, 결합 불필요 / 평균·Best Θ(n lg n), Worst Θ(n²)
- **최악 회피**: 랜덤 피벗, Median-of-3
